开始使用

连接模型

Drora 支持多种方式接入 GLM 模型用于编程工作流。推荐在桌面端登录 BigModel 或 Z.ai 账号运行 GLM-5.3，账号登录即可使用，配置简单；也可以用 API Key 接入常见模型服务，或添加完全自定义的端点。CLI 通过 drora login 完成浏览器授权。

推荐方式

登录 BigModel 或 Z.ai 账号即可在 Drora 中使用 GLM 模型。若账号已开通 GLM Coding Plan 编程套餐，Drora 会直接使用该账号下的套餐与额度。

GLM Coding Plan（BigModel）

国内首选。适合 GLM-5.3 编程工作流、账号登录即用，以及已开通 GLM Coding Plan 的国内用户。

Z.ai Coding Plan

海外推荐。海外用户推荐通过 Z.ai 账号运行 GLM-5.3，同样使用 GLM Coding Plan 套餐与额度。

套餐档位、用量规则与额度以 BigModel / Z.ai 订阅页为准；账号开通套餐后，Drora 会直接使用该套餐额度。

CLI 通过 drora login 完成浏览器授权；无浏览器环境加 --no-browser 手动打开授权链接。 drora logout 清除已保存的登录凭据；会话内也可用 /login 与 /logout。

drora login # 浏览器授权登录 Z.ai drora login bigmodel # 登录 BigModel drora login zai --no-browser # 不自动打开浏览器，手动打开授权链接 drora logout # 清除已保存的登录凭据

其他接入方式

「第三方供应商」：接入兼容 Anthropic / OpenAI 协议的模型服务，包括团队自建通道。

「使用 API Key」：如果你自行管理模型访问，可使用 API Key 直接接入模型服务。

供应商目录

在「设置 → 模型设置 → 添加供应商」的供应商目录中选择模板，填入 API Key 即可。目录覆盖常见的官方与聚合服务：

供应商 说明
Z.ai API / BigModel API 智谱开放平台接口，Coding Plan 之外的 API 接入方式
Anthropic / OpenAI / xAI 官方接口
OpenRouter 聚合多种模型的中转服务
Kimi / MiniMax / DeepSeek / 阿里云百炼 / Xiaomi MiMo 国内模型服务
自定义端点 任何兼容下述 API 格式的服务
供应商目录随客户端内置（仓库 config/provider/drora-builtin.json ，目前 20 个模板）；也可改用本地配置文件，见 相关环境变量。

配置入口

方式一：首次启动欢迎页

首次打开 Drora、还没有可用模型时，欢迎页面会直接提供接入选项：

  • 「连接 Z.ai 继续使用」：通过 Z.ai 账号授权登录。
  • 「连接 BigModel 继续使用」：通过智谱 BigModel 账号授权登录。
  • 「使用 API Key」：直接填写 API Key，进入模型供应商配置。

选择「连接 Z.ai」或「连接 BigModel」后，应用会弹出授权窗口并等待平台完成认证，认证通过后即自动绑定账号。

方式二：模型选择器

进入 Drora 后，点击对话框中的模型名称打开模型选择器，在列表底部点击「管理模型」，即可进入「设置 → 模型设置」面板，管理 Drora Agent 可用的模型通道。

BigModel / Z.ai API 端点说明

通过「编程套餐」授权绑定账号（非 API Key 模式）时，Drora 会自动选择正确通道，无需手动填写。使用 API Key 时，供应商目录中的模板已按账号类型预填接口地址；手动核对时，先选你的账号类型，再按所用平台填写对应地址，并使用对应的 API Key。

供应商模板 接口协议 接口地址
Z.ai Coding Plan Anthropic https://api.z.ai/api/anthropic
Z.ai API OpenAI Chat Completions https://api.z.ai/api/paas/v4
BigModel Coding Plan Anthropic https://open.bigmodel.cn/api/anthropic
BigModel API OpenAI Chat Completions https://open.bigmodel.cn/api/paas/v4
资源包 / 充值余额等通用 API 场景请使用 OpenAI 通用端点（paas/v4），不要选择 Anthropic 协议；Coding Plan 套餐额度请使用对应的 Coding Plan 模板。

连接 BigModel

  1. 通过上述任一方式进入「模型设置」面板。
  2. 在左侧供应商列表中选择「BigModel」。
  3. 完成账号连接并开启启用开关，即可按账号权限使用 GLM-5.3、GLM-5.3-Flash 等内置模型。
  4. 右上角可切换连接方式：使用「编程套餐」绑定 GLM Coding Plan，或改用 API Key 接入。

使用团队套餐

如果你所在的团队开通了 GLM Coding Plan 团队版，登录后不需要额外配置：在 BigModel 供应商页面的「连接方式」菜单里，你有权限的每个团队会各自显示成一个「团队套餐」条目（按组织名称命名），选中即用该团队的额度跑任务。同一个菜单里也能切回「个人套餐」或 API Key。

切换连接方式后，侧边栏和用量统计展示的额度会跟着切到对应来源，额度卡片上会标明是个人还是团队。

如果菜单里看到团队条目却提示「团队套餐未分配」，说明管理员还没给你分配席位——席位的添加和管理需要到 BigModel 的团队套餐管理页完成，客户端里做不了，页面上有直达入口。

使用 API Key 接入

根据你的账号类型选择连接方式：

方式 A：GLM Coding Plan（编程套餐 API Key）

  1. 在 BigModel 供应商页面右上角，将连接方式切换为「API Key」，选择「BigModel Coding Plan」模板。
  2. 接口地址使用模板预填的 Anthropic 接口地址 https://open.bigmodel.cn/api/anthropic。
  3. 填入从智谱开放平台获取的 API Key。
  4. 可用模型以账号权限和供应商返回的模型列表为准。

方式 B：模型资源包 / 充值余额

  1. 在 BigModel 供应商页面右上角，将连接方式切换为「API Key」，选择「BigModel API」模板。
  2. 使用 OpenAI 协议，接口地址填写 https://open.bigmodel.cn/api/paas/v4。
  3. 填入从智谱开放平台获取的 API Key。
  4. 可用模型以账号权限和供应商返回的模型列表为准；也可以点击「添加模型」补充其他可用模型。
资源包 / 充值余额场景不要选择 Anthropic 协议。

连接 Z.ai

Z.ai 是面向海外用户的接入方式，配置流程与 BigModel 基本一致：

  1. 通过上述任一方式进入「模型设置」面板。
  2. 在左侧供应商列表中选择「Z.ai」。
  3. 完成账号连接并开启启用开关，即可使用 GLM-5.3、GLM-5.3-Flash 等内置模型。
  4. 右上角同样可以在「编程套餐」与「API Key」两种连接方式之间切换。

连接后，供应商页面会展示当前套餐与今日各模型的余额、已用量。

使用 API Key 接入

根据你的账号类型选择连接方式：

方式 A：GLM Coding Plan（编程套餐 API Key）

  1. 在 Z.ai 供应商页面右上角，将连接方式切换为「API Key」，选择「Z.ai Coding Plan」模板。
  2. 接口地址使用模板预填的 Anthropic 接口地址 https://api.z.ai/api/anthropic。
  3. 填入从 Z.ai 平台获取的 API Key。
  4. 可用模型以账号权限和供应商返回的模型列表为准。

方式 B：模型资源包 / 充值余额

  1. 在 Z.ai 供应商页面右上角，将连接方式切换为「API Key」，选择「Z.ai API」模板。
  2. 使用 OpenAI 协议，接口地址填写 https://api.z.ai/api/paas/v4。
  3. 填入从 Z.ai 平台获取的 API Key。
  4. 可用模型以账号权限和供应商返回的模型列表为准；也可以点击「添加模型」补充其他可用模型。
资源包 / 充值余额场景不要选择 Anthropic 协议。

Anthropic（Claude API）

  1. 进入「模型设置」面板，在左侧供应商列表选择「Anthropic」模板；目录外也可在列表底部点击「添加供应商」，名称填写「Anthropic」。

  4. 保存后，点击「添加模型」手动填写 Anthropic 支持的模型 ID。
  5. 开启启用开关即可使用。

自定义供应商（兼容 Anthropic / OpenAI 协议）

Drora 支持添加任何兼容 Anthropic / OpenAI 协议的模型服务作为自定义供应商——既可以是公网模型服务，也可以是团队统一维护的企业模型通道或内网自托管服务。

填写接口地址和 API Key 后，通过「添加模型」手动填写该服务支持的模型 ID 即可使用。

配置步骤

  1. 进入「模型设置」面板。
  2. 在左侧供应商列表底部点击「添加供应商」。
  3. 自定义填写名称：为供应商命名（如 claude、deepseek 等）。
  4. 选择对应厂商 Base URL：从下拉列表中选择或手动输入 API 基础 URL。
  5. 填写 API Key：输入对应服务的 API 密钥。
  6. 添加模型：点击「添加模型」，手动填写该服务支持的模型 ID。
  7. 开启启用开关后即可开始使用。

以 DeepSeek 兼容接口为例：

  • 名称填写「DeepSeek」。
  • Anthropic 接口地址填写 https://api.deepseek.com/anthropic。
  • OpenAI 接口地址填写 https://api.deepseek.com/v1。
  • 填入从 DeepSeek 开放平台获取的 API Key。
  • 点击「添加模型」填写 DeepSeek 支持的模型 ID（如 deepseek-chat、 deepseek-reasoner），或团队约定的模型 ID。
  • 点击保存即可。
字段 说明
Base URL 模型服务的 API 地址
模型 ID 请求时使用的模型名，可添加多个模型
API 格式 三选一：Chat Completions、Responses、Anthropic Messages

每个模型还可单独配置 上下文窗口、 最大输出 Token、 输入模态（文本 / 图片 / 视频 / PDF）与可选的推理等级。开启「智能配置」时，Drora 按模型 ID、Base URL 和 API 格式自动匹配推荐配置；手动修改过的字段转为手动管理，其余仍自动跟随更新。

团队使用建议：企业模型通道建议由团队统一管理 Base URL、API Key、模型列表与访问权限，保证长任务执行过程中的连接稳定性和可追踪性。

单个模型的高级参数

在「设置 → 模型供应商」里点开某个模型，展开「高级」，可以为这一个模型单独设置「最大输出 Token」——也就是它单次回复的长度上限。

默认留空，跟随模型自己支持的上限，通常保持留空就好。只有当你确定某个模型能输出更长内容、而 Drora 没有识别到时，才需要手动调大。

调大之后要留意：输出空间和历史对话共用同一个上下文，输出上限调得越高，能带上的历史对话就越少，自动压缩也会来得更早。

上下文窗口：哪些能改、哪些不能

同一个「高级」面板里也能看到模型的「上下文窗口」。三类模型的行为不同：

  • 自定义供应商的模型：可以修改，保存后对新会话生效。
  • 编程套餐（Coding Plan / Start Plan）的内置模型：上下文窗口由服务端统一下发，本地修改会在下一次同步时恢复为官方值——这是有意设计，不是配置丢失。
  • 名称以 [1m] 结尾的模型：固定按 1M 上下文处理，不可修改。

会话的「自动上下文压缩」会在接近窗口上限前提前触发：系统会为模型输出预留空间并保留安全缓冲（合计约 3.4 万 token），因此压缩点低于窗口标称值属于正常现象——例如 128K 窗口约在 9.4 万 token 时触发，1M 窗口约在 96.6 万 token 时触发。自动压缩目前没有可配置的开关或阈值。

思考强度

Drora 会根据当前模型的实际能力显示可用的思考强度（推理档位），不同模型的档位并不相同，界面会按从低到高排列这些选项。选择档位后，Drora 再按当前接口的协议转换请求参数（OpenAI 兼容接口与 Anthropic 兼容接口使用各自的思考参数字段）。如果某个第三方模型没有显示细分档位，通常表示还没有该模型的档位映射，并不是配置丢失。

需要注意：同名模型的第三方部署，接受的档位可能与官方端点不一致——此时选最高档可能返回 400 参数错误，改选低一档即可正常使用。非推理模型则通常只有「开启 / 关闭」两档，或不提供档位。

图片输入的支持判定

Drora 会综合供应商与模型配置、模型目录中的能力信息、内置模型规则，以及当前接口协议，判断所选模型能否接收图片。判断结果分为三种：

  • 支持：保留图片，并随请求发送给模型服务。
  • 不支持：在请求发出前移除图片数据，并用文字提示替代，避免把不受支持的图片传给模型服务。
  • 能力未知：不提前拦截图片，由模型服务最终决定是否接受；如果服务端不支持图片，请求可能直接报错。

通过编程套餐连接 BigModel / Z.ai 时，内置的 GLM-5.3-Flash 是面向截图理解、看图分析和视觉问答的多模态模型，选中它后发送图片会直接按「支持」处理，无需额外配置。

模型 ID 会参与能力匹配，但并非唯一依据。同一个 GLM 模型通过不同供应商或接口协议接入时，判断结果也可能不同。

遇到图片相关报错时，建议先使用供应商文档中的标准模型 ID，并确认当前接口本身支持图片输入；如果使用自定义模型或第三方部署，还应在模型配置中明确声明图片能力。无法确认时，请暂时不要在该模型下发送图片。

HTTP 代理的作用范围

设置中的 HTTP 代理并非「全局代理」，它覆盖的流量范围如下：

走代理：模型 API 请求、MCP 服务器（stdio / HTTP / SSE 三种连接方式）、WebFetch 网页抓取、终端命令子进程（注入 HTTP_PROXY 等环境变量）、插件市场、应用内页面加载。

不走代理：桌面端的账号登录与后端服务请求、Web 远程控制通道（WebSocket）、SSH 远程连接。

  • Drora 默认「不」读取系统的 HTTP_PROXY / HTTPS_PROXY 环境变量（仅 WebFetch 在未配置代理时会兜底使用），以设置页里填写的代理为准。
  • 修改代理设置后需要「重启 Drora」才会对全部链路生效。

验证配置

配置完成后，在对话框的模型选择器中选择对应通道，发送一句简单指令测试，确认模型可用、响应稳定即可开始使用。每个模型配置提供「测试模型」：发送一条固定探测消息验证连通性。会话中通过聊天工具栏的「管理模型」或 /model 切换当前模型；实际消耗的 Token 与调用次数见 使用统计。
