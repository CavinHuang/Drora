# Drora 人格系统：诊断与记录边界（使用者说明）

- 日期：2026-10-31；依据[唯一主 spec](../../specs/drora-persona-system.md) §7「诊断记录、学习输入与安全承诺」与[数据合同](drora-persona-data-contracts-2026-10-29.md) §5。
- 本文是面向使用者的简短说明，只描述已实现的行为边界，不新增承诺。产品设计基线以 spec 为准。

## 1. 人格内容会出现在哪些记录里

| 通道 | 是否包含人格内容 | 说明 |
| --- | --- | --- |
| 真实模型请求（主对话） | 是 | 人格核心与已启用的交流默认（E/U 生效时）作为请求的一部分发送给当前选择的模型 |
| model-io 诊断 | 是 | 真实请求的诊断记录包含实际发出的请求正文；沿仓库既有的脱敏/保留/轮转规则，不为人格功能另设一套 |
| canonical 聊天历史 | 否 | 人格贡献只附加在请求投影上，不写回消息历史；聊天记录里不会多出一条「人格消息」 |
| 辅助请求（标题/摘要/验证等） | 否 | 辅助用途的直接输入从常规上下文组装，不携带人格贡献参数 |
| 新的自动学习（P1b） | 仅限定输入 | 学习输入只有来源 owner 提供的有界原始人类消息窗口；抽取端口没有任何文件、shell 或日志读取工具 |

## 2. 需要如实了解的间接读取路径

- **旧项目 Memory 的文件工具保持原样**：已获准的 Memory 工具仍可按原权限读取本地文件。如果诊断文件或导出的 JSON 落在它们可读的位置，工具结果里可能出现人格正文。这是既有能力的边界，本功能不为人格收窄旧 Memory，也不宣称「任何工具都无法读到人格原文」。
- **独立库不是安全沙箱**：persona.sqlite 与同用户权限下的其他文件一样，可被同用户的任意代码读取或修改。人格系统不声称对同用户工具做硬隔离。
- **Dream 未启用**：既有的 Dream handler 保留在代码中，但本功能没有为它增加任何调度或产品入口；未来若要自动消费诊断，必须先通过单独的安全审查。
- **忘记是逻辑撤销**：forget 清除应用可访问的正文并设置屏障，但不承诺介质级擦除，也不删除旧聊天、原项目 Memory、既有诊断或你已保存的导出文件。

## 3. 新学习通道没有日志入口

自动学习的抽取端口（P1b）：

- 输入只有来源 owner 复验后的消息窗口（最多 8 条原始人类消息、合计 8,000 code point）；
- 没有文件读取、命令执行或 model-io/诊断读取工具；
- 模型输出只经严格校验进入候选，「已记住」之类的模型自述不构成写入。

因此「模型通过学习功能偷读诊断日志」没有实现路径；但请注意这条保证只覆盖新学习通道本身，不覆盖第 2 节列出的既有工具能力。

## 4. 关系最近的设置

| 设置 | 影响 |
| --- | --- |
| 人格执行许可（E） | 关闭后新会话不再捕获人格贡献；已存资料保留 |
| 交流默认（U） | 关闭后偏好不再注入请求（同一事务关闭自动学习） |
| 自动学习（L） | 关闭后停止接收与提交学习工作；已存有效值仍按 U 的状态注入 |

设置页的文案与本说明一致；若两者出现矛盾，以 spec 与本文引用的合同为准，并欢迎反馈。
