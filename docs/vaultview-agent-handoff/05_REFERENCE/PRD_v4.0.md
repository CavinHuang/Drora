## 0. 本轮执行结论

产品不是“新的 Obsidian Agent”，而是 **Drora VaultView：把收藏的文章和笔记变成随时能通过对话找回、阅读和复用的知识源**。用户的首要任务是忘记标题与路径后用自然语言找到“那篇文章”，第二任务是基于确凿原文回答问题、跨文章对照；知识洞察与写回审核是后续增强，不抢占首屏。

**核心承诺**：找回候选有原文、找不到明确说找不到、跨文章回答有逐条证据、原文修改后不沿用过期引用。**不承诺**：所有问题都可以回答、所有收藏日期准确、Jev 分数等同于准确率、严格跨进程原子文件 CAS。

**核心体验链**：输入零散线索 → 意图与限制条件 → 混合召回 → 本地首屏 → 可选 Jev 重排+证据分类 → 证据充分性决策（必要时扩搜）→ 当前原文版本核验 → 找文章返回候选 / 问内容生成证据绑定回答 → 生成后语义支持核验 → 打开来源与持续追问。

**导航规则**：Drora 现有一级 `Vault` → VaultView 内 `笔记 / 智能问库 / 洞察 / 审核`。Vault 设置以右上角配置入口或索引状态入口进入；无额外 Knowledge 一级导航、无第二套 Agent 会话。

## 1. 背景、任务与成功条件

### 1.1 核心用户问题

用户从网页、微信公众号、技术文档、论坛等收藏大量信息到 Obsidian，笔记标题常常不可预测，正文有长文章、网页摘录、列表、代码块和双链。几周后仅记得观点/场景/一部分原句，传统文件树与关键词搜索要求用户已经知道怎么命名。

核心 JTBD：**当我模糊记得曾收藏一篇资料时，我想通过一句自然语言找回原文及其关键段落，以便继续阅读、引用或给 Drora Agent 使用，而不是重新上网搜索。**

### 1.2 用户任务与优先级

| 任务 | 用户自然表达 | 完成标志 | 优先级 |
|---|---|---|---|
| 找到某篇收藏 | “收藏过一篇说长上下文无法代替长期记忆的文章” | 正确原文候选出现在前 5 且可定位 | P0 |
| 直接问文章内容 | “我笔记里怎么解释 Agent 的长期记忆？” | 每个核心主张对应可核验证据 | P0 |
| 对比多种观点 | “我收藏的两种记忆方案区别是什么？” | 多源对照，不把未提及当反对 | P0 |
| 忘记表达形式 | “好像有人说 token 多不代表有记忆” | 同义语义召回，并可缩小范围 | P0 |
| 继续限定 | “仅看我在今年收藏的”“就比较这两篇” | 继承会话中的用户选择及硬过滤器 | P0 |
| 发现相互矛盾 | “我的笔记里有没有相反结论？” | 洞察有证据、能核对 | P1 |
| 纠正已有笔记 | “根据这三篇文章补齐指南” | 可审阅 Diff 并安全应用 | P1 |
| 自动整理收藏 | 入库标签/摘要/推荐 | 未经授权不改原文 | P2 |

### 1.3 反目标

不重做 Drora Agent Runtime、Obsidian 原生编辑器、插件商店、移动远控；不要求 Vault 迁移；不默认扫描其他工作区；不把搜索结果自动写成 Memory；不将 Jev 当作完整安全筛查；不把云端配置作为 P0 的强制依赖。

## 2. 产品范围和信息架构

### 2.1 四视图

| 页面 | 默认角色 | 核心区域 | 关联能力 |
|---|---|---|---|
| V01 笔记 | 现有用户的熟悉入口 | 文件树 + Markdown 编辑器 + 可折叠相关笔记 | 选区引用、打开当前文问答、原文回跳 |

| V03 洞察 | 低打扰后台建议 | 证据卡片 + 差异与时效解释 | 冲突提示、相关内容、反馈、拒绝推送 |
| V04 审核 | 受审知识修改入口 | 待审列表 + 来源 + Diff + 操作记录 | L2 Proposal、批准、拒绝、重新审核、Undo |

### 2.2 对现有 Drora 的尊重

- `[现有]` VaultView 具有文件树/Markdown 阅读编辑、选区动作、焦点上下文注入，不推倒重来。
- `[现有]` Agent 原生 Read/Write/Edit/Glob/Grep；`allowAgentWrites=true` 的 PermissionRequest hook 会自动批准根内写入（不等于 L2 Proposal 通过）。新版本必须增加确实覆盖执行边界的分级策略。
- `[现有]` Drora 的会话、Task queue、远程手机 attachment 归现有 Host，不创设 Knowledge 专属 Agent 会话历史。
- `[现有]` Memory Service 面对项目记忆目录，Memory Agent 属 CLI；Knowledge 索引与 Memory 写入不是同一系统。
- `[决策]` Obsidian 配置仍按当前单活动 Vault 工作；未来多源可作为 SourceAdapter 扩展，不在 MVP 改配置形态。

## 3. 检索交互统一原则

1. **用户优先看到可点击文章**：FIND 不生成抢占首屏的长答案，ANSWER/COMPARE 才显示结果正文。
2. **先显示本地结果，异步增强**：Jev 花费超过预算或拒绝授权，用户仍能操作原结果，任何后台重排不得替换已打开候选。
3. **重排是建议，不是事实**：用户不看到“匹配率 97%”；展示“明确提及目标观点 / 部分相关 / 仅主题相似”等可解释标签。
4. **证据透明**：候选显示文件名、标题路径、命中原句、收藏日期仅在存在真实字段时显示；点击后实时验证源版本。
5. **不确定时留后路**：若召回覆盖不全或语义模型不可用，永不宣称“全库没有”。无可靠唯一命中时返回多篇候选或请求补充线索。
6. **控制噪音**：默认隐藏 Decision Trace、工具明细和请求费用；排障时一键展开。
7. **无数据出站默认**：启用 Jev 前必须明确本次发送的 query 与候选片段、服务商、范围、期限，拒绝不影响本地检索；语义 embedding 另设独立策略。
8. **普通会话不改写 Vault**：任何 L2 长期知识沉淀必须形成 Proposal；L3 高风险批量操作在强制门禁未完整实现前不得允许运行。

## 4. 逐屏交互与异常状态（交付 9 屏）

### V01｜笔记 + 相关资料

**进入**：Vault 一级入口默认此页；从引用点击回到此页并携带 `sourceId, path, hash, heading, selector`。左文件树 / 中编辑 / 右相关资料作为可折叠辅助区，不丢编辑草稿与滚动位置。

**核心动作**：选择笔记、全文阅读、选中文本 → “引用到当前 Agent”或“就此问库”；相关笔记点击后仅预览/打开。外部修改触发草稿冲突提示，不静默覆写。

**异常**：Vault 未配置显示连接引导；文件被删除显示失效信息并保留可用草稿；没有相关笔记显示克制空状态；引用定位段落变化显示“原文已变化，请重新定位”。

### V02｜智能问库 - 初始态

输入区有三种目的：`自动识别（默认）/ 找文章 / 问内容 / 比较`，输入多行自然语言；Enter 提交、Shift+Enter 换行（在 IME 拼音组合中不触发）。上方建议查询只用于引导，不是真实用户数据。

辅助范围：当前授权 Vault / 文件夹 / 实际收藏时间字段（若不存在隐藏此筛选）/ 是否排除某标签。右侧信息区默认是查询说明、索引覆盖和隐私状态，用户可隐藏。

**空态**：提示“描述你记得的观点、场景或片段即可”；没有 Vault 时出现可进入授权设置的引导；索引尚未开始显示启动操作。

### V03｜找文章 - 正常命中

输入后立即显示阶段状态“检索中”，本地召回首批结果即可展示，不必等 Jev。列表按文章聚合，默认展示 3–5 篇、可展开更多；每篇只露出最匹配段落而非重复同文多个 chunks。文章条目有“为何候选”“原文片段”“所在文件/章节”“打开原文”“加入当前 Agent”。点击条目使右侧显示具体版本核验细节。

完成 Jev 决策后，排序可以更新，但正在查看的卡片 selectionId 保持固定；上方显示“排序已优化，可查看变更”，不抖动滚动位置。用户可以固定某篇文章继续问，而不必重新搜索。

### V04｜问内容 - 有来源的答案

基于同一 Query pipeline 选出符合证据门禁的片段，生成一个有界证据包，经 Drora 既有 Session 生成答案。答案采用“核心结论 → 引用编号 → 展开原文”；右侧为来源检查。答案生成后仅在语义核验和确定性校验都通过时显示“已验证引用”；不通过标注“不足以支持 / 存在相反证据”，提供重新生成或移除表述。

**异常**：所选生成模型不可用时保留完整检索候选，不清空搜索；引用文件变化时撤销“已验证”标识。

### V05｜多文章比较

用户通过显式“比较这些文章”或自然意图进入；至少两篇受信文章。用三列“比较维度 / 文章 A / 文章 B”；每一事实单元含来源指向、空字段显示“未提及”，互相矛盾时分来源展示各自前提。用户可以剔除某一篇后重新比较；同一源多个 chunk 聚合为一篇。

### V06｜模糊匹配 / 无答案 / 需澄清

当 Jev 相关性信号弱、候选接近或直接证据不足：代码最多执行**一次受控扩大检索**（同义词、相邻标题、移除非硬性检索关键词；不能删除用户明确的时间、目录限制）；若仍无明确匹配，展示多篇近似文章和差异，而不是强行给 Top1 宣称找到。

当搜索结果为空：明确区分“无可靠命中”与“当前索引未覆盖/服务不可用”。询问“能否记起作者、观点关键词或大致时间？”只是可选后续动作，绝不反复循环。

### V07｜索引 partial / Jev 降级 / 来源过期

在结果顶部固定一条低噪音状态说明；结果卡仍可读。索引 partial 显示已完成与排除项数量；远程 Jev 降级（未授权/超时/429/无效输出）使用本地候选顺序并告知“本次只使用本地排序”；引用 stale 在打开时实时核验并阻断旧定位。

### V08｜知识洞察与审核

洞察仅给“可能相关/存在差异”的候选，必须附原文证据，默认不弹窗；反馈可隐藏/稍后。审核分为“待审核 / 已处理 / 需处理冲突”；Diff 显示修改范围、来源和目标文件当前 hash。批准绑定 proposalRevision + sourceEpoch + fileSha。被外部改写后必须重新比较、重新批准；Undo 也需要当前版本校验。

### V09｜隐私、模型、设置与移动适配

Vault 设置通过右侧抽屉集中：授权状态、索引健康、词法/语义模型是本地还是远端、Jev 出站（默认关）、调用预算、排除目录、清空可重建索引。切换 Vault 后 sourceEpoch 变化旧结果失效。移动 Web 作为现有远控的延展，首期提供查看文章、证据和阅读状态，不能单独创建第二套执行服务。

## 5. Jev 多阶段决策设计（本轮核心）

### 5.1 责任矩阵

| 阶段 ID | 时机 | Jev 问题/原语 | 是否必须调用 | 安全执行方 | 输出分支 |
|---|---|---|---|---|---|
| J0 入库类型 | 索引阶段 | 收藏文章/个人笔记/摘录等 Choice | P2 | 索引服务 | 仅分类标签，绝不改原文 |
| J1 查询意图 | 查前 | FIND/ANSWER/COMPARE/EDIT/UNKNOWN Choice | 可选 P0 | IntentPolicy + 用户手选优先 | 进入哪种输出形态 |
| J2 歧义判断 | 查前 | 是否需要用户补充关键实体/范围 Noul | P1 | 业务代码 | 检索 / 显示可选澄清 |
| J3 候选命题匹配 | 本地召回后 | 是否明确含目标观点 Noul | 推荐 P0 | RerankPolicy | 重排文章候选 |
| J4 证据资格 | 与 J3 同一 candidate state | relevant / direct / contradictory / injectionRisk 多 Noul | 推荐 P0 | EvidencePolicy + source verifier | 分为直接、反证、背景、隔离 |
| J5 充分性判断 | 聚合检索后 | 证据能否回答 / 是否应扩大搜索 Noul/Choice | 可选 P0 | BranchPolicy | 返回 / 扩搜一次 / 无答案 |
| J6 引用支持关系 | Agent 回答后 | SUPPORTED/CONTRADICTED/UNSUPPORTED/UNCERTAIN Choice | 推荐 P1 | CitationVerifier + SupportPolicy | 展示验证、修正或标不确定 |
| J7 追问指代 | 连续对话 | 此处“它/那篇”所指哪篇 Choice | P1 | session scoped context + 用户确认 | 复用当前源 / 新查询 |
| J8 修改风险 | 写回前 | 普通编辑/知识沉淀/批量破坏性 Score/Choice | P2 辅助 | **硬权限门禁 + 人工审核** | L1/L2/L3，Jev 不能放行 |

### 5.2 不是每次都执行 9 次

**常见 FIND（正常）**：本地规则/可选 J1 → 检索 → 同一批 J3+J4 → J5 → 文件真实性核验 → 展示候选。不调用 Agent 生成与 J6。**ANSWER**：增加 Agent 生成与 J6；J6 仅对声明性主张（由规则拆分 / Agent 结构化提供）验证。**用户手动选择模式**：跳过 J1。**明确标题精确命中且原文可验证**：可跳过 Jev 重排避免浪费。**没有远端授权**：全部走本地路径，不发任何 Jev 请求。**J5 决定 expand**：扩搜上限一次，不出现模型驱动无限循环。

### 5.3 决策与硬规则的边界

- Jev 输出**建议**：相关、可能支持、存在矛盾、需要扩搜、追问可能指向何处。
- 硬规则决定：已授权 sourceId/sourceEpoch、目录和日期筛选、真实来源存在、文件 SHA 及引用定位、最大检索轮数、数据出站批准、敏感路径/文件写权限、Budget 与超时。
- Jev 不能从正文执行指令；正文内容只作为不可信状态数据。Jev 的 injectionRisk 判断用于辅助标记，**不代表安全防线**。
- `Noul` 数字是模型估计，`Score` 分级不是“准确率”，只能在开发诊断面板中显示原始值，最终用户以文字解释为主。
- `Choice` 必须包含 `unknown/none` 分支，既避免强迫路由，也避免在所有候选都错时选一个。

### 5.4 Jev 输入范围与预算（建议值，需实测）

每次评估 candidate 的 state：`query + intent + candidateId + title + heading + necessary passage (≤1200中文字符)`；J3/J4 可以作为**同一 candidate state 的多问题**调用，避免重复发送。默认候选池 Top30 chunks，Jev 优先 Top12–20（分两批渐进式），并发≤4，整阶段软预算 4s/硬预算 8s（实验值），结果应立即保留本地首屏。禁止发送用户绝对路径、模型 API Key、其他会话历史、未授权 Vault 内容。开启“仅本次授权”到期即失效，新的源范围、新模型或新会话都需要重新授权。

查询新 query、sourceEpoch 更新、Tab 被关闭时取消请求，并由 `queryGeneration` 拒绝迟到响应。Jev 超时、响应结构异常、429 或网络错误：优雅回退，不删除召回结果；可单独“重试智能排序”。多候选有部分结果：不将已排序与未排序分数直接混排成貌似完整模型排名，保留本地基线作为安全顺序。

### 5.5 BranchPolicy 受控分支

`VALID_FIND`：已经有可核验的目标命题原文且用户目的是找文章 → 返回候选；`VALID_ANSWER`：证据可以支持至少一个主张且无阻断 → 生成证据回答；`EXPAND_ONCE`：召回覆盖满足但证据不足，可在固定预算内扩大一次；`AMBIGUOUS`：有多个近似候选 → 标不确定并让用户选择；`INSUFFICIENT`：无直接证据 → 不生成断言；`DEGRADED`：索引/外部模型不可用 → 提供本地已有候选并展示缺口。用户明确指定的筛选条件不可由 J5 解除。

## 6. 检索、索引与证据

### 6.1 可重建索引

SourceRegistry 读取现有活动 Vault 配置，对文档建立 `sourceId / sourceEpoch / path / fileSHA / indexedAt`，将 Markdown 按标题及自然段落切块，保留 frontmatter、wikilinks 和代码块的原始语义。FTS 需要实测中文 tokenizer，必要时对中英混合做自定义 n-gram 与术语归一；Embedding 本地/远程单独开关。索引由 watcher+reconcile 维护，漏事件不能无限留脏；跨两个 Host 以共享 DB lease/fence 协调，绝不把 Renderer localStorage 当权威索引事实。

召回时进行：hard filters → 词法检索 + 可用的 embedding → RRF / rank fusion → chunk 去重与文章聚合 → J3/J4 → sourceVerifier。Jev 不负责召回被遗漏的文档。

### 6.2 可验证引用

真实可点击引用必须由 Knowledge Service 基于授权源签发 `EvidenceReceipt`（sourceId, sourceEpoch, relativePath, contentHash, headingPath, quoteSelector, queryId, sessionId）。UI 点击时重新校验权限、文件 SHA 与文本锚点，stale 时显示“原文变动、需要重定位”并且不使用过期行号。LLM 自报的 path/citationId 一律视为不可信文本。

### 6.3 对话与 Session

搜索请求本身只由 Knowledge Service 管理 `queryRunId`、缓存与可观测性；**消息生命周期由 Drora 现有 Session 持有**。`@Vault` 预检索输入在真实 submit/admission 边界必须重新核验；Busy queue、恢复、异地远控重连期间，不允许引用已撤权源内容。产生回答前按用户选择的模型出站策略显示证据范围并征得权限，不能把 Jev 授权误用作生成模型的出站授权。

## 7. 风险分级写回（既定方案 C）

| 级别 | 例子 | 判定 | 允许操作 |
|---|---|---|---|
| L0 | 检索/阅读/证据比较 | 无副作用 | 直接 |
| L1 | 明确目标的单文件小范围 `.md` 编辑 | Runtime 权限+操作范围 | 继承现有授权，必要时逐次确认 |
| L2 | 形成长期决策/写知识总结/替换已整理观点 | **结构化 Proposal + Diff + 人工批准** | CAS 检查/写入账本/撤销 |
| L3 | 批量删除、移动、重构、修改 `.obsidian` 等 | 硬风险限制 | 强门禁未完全验证前不得开放自动执行 |

`allowAgentWrites` 不能等同于全部等级放行。现有 PermissionRequest 仅覆 Write/Edit，无法单独保证 Bash、其他插件或外部工具的写盘隔离。T0 必须核查执行面，不能把 prompt 想象成安全策略。Proposal Approval 绑定版本，用户批准前不写盘；重试以 operationId 幂等，状态 unknown 必须 reconcile；文件外部竞争窗口仍需补强，不能声称与 Obsidian 进程形成真正的跨进程原子 CAS。

| 状态 | 用户看见 | 主操作 | 禁止行为 |
|---|---|---|---|

| `indexing` | 索引正在建立，结果可能不完整 | 继续用已索引内容 | 宣称全库已搜索 |

| `deciding_jev` | 智能排序中（可继续查看） | 停止本次增强 | 自动替换已选文章 |
| `ready` | 找到有证据的候选 | 打开原文 | 宣称模型分数即准确率 |
| `ambiguous` | 有几篇符合描述，请确认 | 查看差异/继续限定 | 强选一篇 |

## 9. 质量指标与实验

### 9.1 主指标

**North-star**：`verified_retrieval_success_rate` = 已确认找到目标原文且通过引用定位校验的找回任务比例。辅助行为：用户点击并停留原文、标记“就是这篇”、明确否决/反馈。不能用点击率独立代表找对。

### 9.2 按阶段测量而非只看答案

| ID | 指标 | 原因 | 初始实验门槛（非生产承诺） |
|---|---|---|---|
| M01 | Recall@30 | 正确文章有没有被召回 | ≥95%（基于人工标注试点集） |
| M02 | Hit@1/Hit@5、MRR | Jev 是否改善排序 | Jev 方案较本地同集显著提升，无明显负向分布 |
| M03 | Intent Accuracy | 找文章/问内容分支准确 | ≥95%，不明确意图应可手动纠正 |
| M04 | Evidence Precision | 选中原文是否直接支持用户主张 | ≥95%，人工抽样 |
| M05 | No-answer FPR | 没有正确文章仍宣称找到了 | ≤3%，由验证集校准 |
| M06 | Citation Anchor Accuracy | 用户点击引用能定位当前真实原文 | 显示“已验证”的引用 100% 源端存在 |
| M07 | Claim Support Precision | 已验证的声明确由来源支持 | ≥95%，人审抽样 |
| M08 | Routing Agreement | 分支策略与审核期望一致 | ≥95% |
| M09 | Privacy Leak Count | 关闭外发仍有 Jev/remote embedding 请求 | 0 |
| M10 | P50/P95 + cost | 决策深度是否影响可用性 | 设计实验确定，不提前承诺 |

### 9.3 基准实验

先用至少 150 个真实中文 Vault 问题：标题已知/同义描述/只记得观点/时间限定/无答案/多篇冲突/拼写错/多轮指代各有覆盖；每条由人工给目标文章 ID、支持段落与可接受行为。冻结离线评测集，对比 A 本地词法、B 本地词法+语义、C 加 Jev 重排+证据、D 加充分性与引用验证；测漏召回、强选率、端到端成功和延迟费用。

## 10. 版本阶段与评审门槛

| 里程碑 | 范围 | 必经验证 |
|---|---|---|
| **S0 技术 Spike** | 知识索引共享、中文召回、证据进现有 Session、模型外发、权限覆盖 | 双 Host、真 Drora busy queue、文件更新、真实中文集 |

## 11. 验收条件（阻断项）

- **AC01** 手选 FIND 时无需调用 Jev Intent；按 Enter 发起不受 IME 合成影响。
- **AC02** 首屏本地结果在 Jev 之前可交互，关闭 Jev 完成整条找回链。
- **AC03** 正确文档不在 Top30 时系统不伪造结果；评估为召回问题而非重排问题。
- **AC04** 多候选接近时显示多个候选和差异，不强行选唯一。
- **AC05** 无直接证据时至多扩搜一次，且不移除硬筛选与权限。
- **AC06** 修改 query/切 Vault 后旧 Decision 与 Receipt 不能覆盖新状态。
- **AC07** Jev 单次外发授权仅对指定 query/range 生效；拒绝后没有任何 Jev 请求。
- **AC08** Jev 超时/429/不合法 JSON/候选 ID 不在池内均回退本地。
- **AC09** `Noul` 概率不对用户显示为准确率；Decision Trace 可人工查看模型来源。
- **AC10** ANSWER 每个被标为受信结论都含有效 receipt 和语义支持判断。
- **AC11** CitationResolver 对文件 SHA 变化、删除、撤权、Vault 切换均返回 stale/forbidden。
- **AC12** COMPARE “未提及”区别于“反对”；保存来源和比较时的前提。
- **AC13** 追问中的“它/那篇”不能越过上次手动选择的来源和文件夹范围。
- **AC14** 索引 partial、embedding 不可用、生成模型离线各自降级，文案准确。
- **AC15** 用户笔记中存在 prompt injection 时，正文只能作为不可信数据。
- **AC16** L2 Proposal 未批准前文件内容不变；重复 apply 幂等、变更后批准作废。
- **AC17** `.obsidian/**`、软链、非 Markdown 与批量破坏性操作不得因 allowAgentWrites 自动获得高等级权限。
- **AC18** 双 Host 共享索引通过 lease/fence 防止旧 generation 回写；索引删除不删 Proposal ledger。
- **AC19** 手机远控不创建新的 Agent Runtime，不产生第二份独立审批事实源。
- **AC20** 页面遵循 Drora `DESIGN.md` 的 `text-ui-*` 与主题语义，深色、浅色、移动宽度不溢出。

## 12. 待确认项（不可当已落地）

1. Jev TypeSafe 供应商接口具体 SDK 版本、生产配额、并发、速率限制与落地凭证策略需 T0 真机验证。
2. Jev J1/J5/J6 是否比本地规则/已有模型更有效，必须经 A/B 决定是否启用；默认关闭不改变。
3. 外部 Embedding 是否启用是**独立授权**；Jev 授权不自动扩展到其他模型。
4. 并发跨进程严格文件 CAS 尚未实证；对外不能宣称绝对不覆盖。
5. HTML 是模拟数据的交互演示，不连接真实 Vault/Jev，也不是从 Drora 编译出来的页面。
