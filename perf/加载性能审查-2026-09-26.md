## 二、分领域发现

### A. Renderer 首屏静态图（最高杠杆）

**现状**：两端 Vite 均无 manualChunks/advancedChunks。desktop 入口 `index.html` 带 280 条 modulepreload、共 8.3 MB raw，主 chunk 单块 5.6 MB。懒加载只覆盖 Office/PDF/图表预览；以下重型面全在首屏静态图里：

- 消息渲染链 `ConversationRowView → message.tsx:41`（Streamdown + @streamdown/code/math/mermaid）→ `code-viewer.tsx`（shiki）→ katex/mermaid 全进主包
- `Root.tsx:17` 静态引入 SettingsPage（1962 行）、SSHDialog、Terminal（xterm 链）
- `@xyflow/react` 被 7 个文件静态引入（canvas 未像 chart 那样隔离）
- `persona.tsx` 静态引 `@rive-app/react-webgl2`
- `LexicalChatInput`（lexical）静态进 ChatPromptEditor

**双 shiki 实例**：ui 直接依赖 `shiki`（10+ 处）+ `tokenlens`（自带一份）+ `@streamdown/code`（又一份），导致 @shikijs/langs 每个语言、onig wasm 都被打 2-4 份（sourcemap 证实 `@shikijs/langs/dist/emacs-lisp.mjs` 存在两份 chunk）。lucide 图标同理（240 个单图标 chunk 多数成对）。

**ui barrel**：`packages/ui/src/index.ts` 39 条 re-export 的巨型 barrel + `package.json` 无 `sideEffects` 声明 → 消费方只拿 `Root` 也会拖入 Terminal/GitGraph/App 整图。

### B. Desktop main 启动链

- 🔴 `await armsInitPromise`（index.ts:2188）排在 `ensurePrimaryWindow`（:2243）之前，ARMS RUM 初始化串行阻塞首窗。
- 🟡 electron-updater 静态 import 且内联进 main bundle（autoUpdater.ts:17，不在 tsup external）；OTel exporter 顶层构造（index.ts:813-827）。二者均不在首窗关键路径。
- 🟡 窗口无 `show:false`+ready-to-show（desktopWindowChrome.ts:565-600），创建即显示、底色透明——加载慢时是「透明空壳」而非骨架。
- 🟢 生产 loadFile 本地文件、Host 进程 dom-ready 后才 fork、agent 异步拉起、autoUpdater/cron 已后台化、login env 预热异步。

### C. Web 端

- 🔴 mount 前串行 await 链：`fetch('/api/server-info')` → WS 握手 → 才 `root.render`（web main.tsx:371→446→452）；首个可交互界面被两次网络往返阻塞。可并行化或先 render 后连。
- 🟡 `DroraIntlProvider` 内 locale 再走一次 useEffect await（IntlProvider.tsx:170）。
- 🟢 静态外壳做得好：主题防闪内联脚本 + 纯 CSS loading 骨架、无外链字体（Inter 走系统栈）。
- 注：web 与 desktop 共用 ui 源码直打包，上述 bundle 问题同样落在 web。

### D. 交互热路径（加载之外的「能用」体感）

- 🔴 草稿持久化：`ConversationComposer.handleEditorChange`（每键击）→ `updateComposerDraft` 同步 `persistV4ComposerDraft` → `composerDraftStore` 全文件读-改-写（composerDraftStore.ts:76-105/144-154）。350ms 防抖只盖 editorStateJson，text 路径裸奔。
- 🔴 流式代码块：`shikiHighlighter.ts` cache key 含首尾 100 字符+长度（:81-85），增长期每 chunk 都是新 key → 每 chunk 全文重 tokenize；完成后才进缓存；`tokensCache` 无淘汰（:60-67）。
- 🟡 Lexical 每键击两次全量 markdown 序列化（LexicalChatInput.tsx:861-862）。
- 🟡 无 CJK 单字节化：中文内容使 V8 字符串走双字节慢路径，正则/tokenize 热路径（技能专门提示的中文产品坑）。
- 🟢 打字不触发会话列表重渲染（局部 state + selector 订阅）；时间线 8 处虚拟化 + 行级 memo；diff 已挪 worker（diffs.worker 808KB，非主线程）。

## 三、按杠杆排序的行动建议（每条附护栏）

1. **去重 shiki/lucide（预计 -9.0 MB raw，先于一切分块）**：vite `resolve.alias` 把 tokenlens/@streamdown/code 内部的 shiki 系列指回同一份，或 rollup `dedupe`。护栏：代码高亮黄金测试（同一文件高亮输出逐字节一致）+ 重复组计数棘轮（本次 533 组→0）。
2. **ui barrel 拆分 + `sideEffects` 声明**：按域拆入口（`@drora/ui/root`、`/terminal`、`/settings`…），补 `"sideEffects": false`。护栏：bundle 审计脚本期望主 chunk 下降；冒烟全入口。
3. **非首屏重型面 lazy**：SettingsPage、Terminal(xterm)、xyflow canvas、rive、mermaid/katex（按块类型出现才加载；streamdown 本体保留首屏）。护栏：每个入口「先加载再调用」冒烟 + 视觉回归（切换不闪烁）。
4. **main 首窗解耦**：ARMS init 与首窗并行/加超时；electron-updater、OTel exporter 改 dynamic import；三次 setting.json 读取合一。护栏：RUM 上报计数不降（防漏报是当初串行的原因，需要用户拍板取舍）。
5. **main/preload V8 code cache**：技能「原文」招式。main 6.3MB ESM 可用 v8-compile-cache 或构建期 bytecode（Agent CLI 已有 `--agent-bytecode` 先例可复用）。护栏：版本升级后缓存自动重建。
6. **草稿持久化防抖**：text 路径复用 350ms 防抖（或 trailing persist + flush on blur/unmount）。护栏：存着草稿时抢先打字，最终内容=草稿+新输入（技能实测踩过的坑）；卸载/发送前 flush。
7. **流式代码块 tokenize 节流**：增长期只对「稳定前缀」tokenize 或 ~150ms 节流，完成后终 tokenize一次；tokensCache 加 LRU 淘汰（上限如 200 条）。护栏：完成后渲染结果与直接全量 tokenize 逐字节一致。
8. **web bootstrap 并行化**：server-info 与 WS 并行，或先 render 带 fallback 再连。护栏：错误路径（server 不可达）仍显示重试 UI。

## 四、健康项（无需动）

静态外壳（两端 index.html 主题脚本+CSS 骨架）、无阻塞字体、reload 全在错误路径、`:has` 无全局贵选择器、打字路径订阅隔离、时间线虚拟化、diff worker 化。
