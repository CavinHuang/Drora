# Product website (GitHub Pages)

## Product rules

- The Drora product website is a fully static multi-page site under `website/`: `index.html` (home), `changelog/index.html` (release notes), `docs/index.html` (documentation), `security/index.html` (vulnerability reporting), `community/index.html` (community channels), `terms/index.html` (usage terms), `privacy/index.html` (privacy notes) and `support/index.html` (feedback & support). Pages share `assets/css/style.css` and `assets/js/main.js`; shared chrome is rendered by `assets/js/components.js`; each page only carries its own content. All cross-page links are relative (`changelog/`, `docs/`, `../`). The site is physically isolated from restored upstream code and from all workspace packages: no package imports it, it imports no package, and it is excluded from workspace lint/format tooling. It ships plain HTML + CSS + vanilla JS with zero build step and zero runtime dependencies.
- The visual design intentionally follows the official ZCode marketing site (https://zcode.z.ai/): dark theme (`#161616` background, `rgba(255,255,255,0.1)` borders), Geist-style system font stack, and a five-section home layout — fixed header, hero with a live DOM app-window mock, three-edition cards (mirroring the pricing card anatomy), three capability cards, download section, footer. Copy and branding are Drora's own and must follow `specs/drora-rename.md`; the site must never claim to be the official ZCode product.
- Shared page chrome and repeated structures are native Web Components (custom elements rendering light DOM, defined in `website/assets/js/components.js`, loaded before `main.js`): `<site-header>` (brand / flex-1 left-aligned main nav / language pill / GitHub pill / mobile menu; `data-page` drives the active-nav highlight, `data-base` fixes relative link prefixes), `<site-footer>` (top rule + copyright row + link group), `<drora-pet>` (sprite + name; owns the atlas background attachment), and `<release-block>` (changelog version block: pill + date + optional download dropdown + title + slotted groups). Their DOM anatomy directly replicates the reference site's rendered markup (sticky header with border, `justify-between` three-part desktop row with a `flex-1` nav, footer `<hr>`, `border-b` release blocks with white-bordered version pills, group headings as `h2`). Visual tokens stay in `style.css`; components carry structure only.
- Because components need JS to render, every page keeps a `<noscript>` fallback nav block; the offline/file:// acceptance scenario therefore means: all page content renders fully without JS, and navigation degrades to the noscript links.
- The docs page layout replicates the reference DOM order: content article first, both sidebars as sticky asides that only display at `xl` (≥1280px) — below that, the page is a single content column exactly like the reference site on mobile/tablet.
- The changelog page replicates the reference release-block anatomy: `border-b`-separated blocks, a meta row (white-bordered version pill, date, download dropdown for the latest release only), then the release title and feature/fix groups whose headings are `h2` elements.
- The docs section replicates the reference site's multi-page docs structure: one page per sidebar item under `website/docs/` (`index.html` = welcome, `install.html`, `configuration.html` (连接模型, mirroring the reference slug), `goal.html`, `history.html`, `remote-control.html`, `remote-dev.html`, `pets.html`, `skin.html`, `usage-stats.html`, `skills.html`, `subagents.html`, `mcp.html`, `hooks.html`, `automation.html`, `cli.html`, `build.html`, `faq.html`, plus the content-alignment round's additions: `agents.html` (Drora Agent), `task-management.html`, `memory.html`, `safety-confirm.html`, `ADE-tools.html`, and `keyboard-shortcuts.html` under a 帮助 group). Every docs page renders the shared sidebar via the `<docs-nav data-current="<slug>">` component (single source of the docs IA; current page highlighted), a breadcrumb row with its group label + 「复制全文」, the page h1 (reusing the nav item key), its own content, and a right "本页目录" TOC that is auto-generated from the page's `h2[id]` elements and hidden when there are fewer than two. The sidebar taxonomy mirrors the reference docs groups (开始使用 / 核心功能 / 深度集成 / 更多), but items only cover capabilities this repository actually ships. Features that are placeholders or absent in this repo (e.g. Computer Use per NOTICE.md, Bot Channel, Wiki, IDE integrations) must not appear. Commands and env keys must be copied from README.md, not paraphrased.
- Content density follows the reference docs pages (subsection tables, code blocks, callouts, grouped Q&A), but every capability assertion must trace to this repository — source files, i18n keys (zh-CN.ts), NOTICE.md or README.md. Reference copy is a structural template only; z.ai-only claims (subscriptions, quotas, team plans, unsupported features) are never ported.
- Docs search indexes the docs IA itself (the same data the sidebar renders, exposed by `docs-nav`): the ⌘K overlay lists matching doc pages and navigates to them. The index and the sidebar share one source, so they cannot drift.
- Body elements of docs pages carry `data-page="docs" data-doc="<slug>"`; `pageTitle` resolves docs titles from a per-slug map.
- Docs-page chrome mirrors the reference docs header: a search affordance and a "复制全文" (copy article) button. Search is a zero-dependency client-side filter over the page's own sections (opened by click or ⌘K / Ctrl+K, closed by Esc); 复制全文 copies the article text via the clipboard API. Both are progressive enhancements: without JS they simply don't render.
- The header nav 社区 item is a dropdown (native `<details>`, mirroring the reference's 社区⌄) listing the community page and the real external channels (飞书 / Discord / Discussions).
- A `404.html` mirrors the reference site's 404: centered code + message + a link home; GitHub Pages serves it automatically for the project site.
- Secondary pages mirror the reference site's navigation and footer targets, but their content must stay faithful to what this community repository actually offers — never port the reference site's commercial claims:
  - `security/`（提交漏洞）: how to report vulnerabilities in this fork — GitHub private vulnerability reporting (`/security/advisories/new`) for sensitive issues, public issues otherwise; scope = the forms this repo ships (desktop app, CLI, web/server); process = report → confirm → fix → disclose with credit; explicitly community-run, no bounty program (the reference site's reward tiers are deliberately not replicated).
  - `community/`（社区）: the real channels only — 飞书社群 and Discord links from README.md, GitHub Discussions, and how to contribute (issue first, then PR). The nav 社区 item points here; the page links out to the channels.
  - `terms/`（使用条款）: short open-source terms — Apache-2.0 license, functional-scope and maintenance disclaimers summarized from and linked to NOTICE.md, upstream trademark note (ZCode/Z.ai marks belong to their owner; Drora is a community remake, not the official product).
  - `privacy/`（隐私说明）: factual data-flow notes — local-first storage (session/config data under the app data directory, CLI db at `~/.drora/cli/db/`), model requests go to the endpoints the user configures, update checks reach GitHub Releases, credentials are not logged; link NOTICE.md §二/§三 for the full matrix. No absolute "we collect nothing" claims.
  - `support/`（支持与反馈）: feedback channels (issues / discussions / 飞书 / Discord) plus what to include in a report (version, platform, steps, expected vs actual) and issue-title conventions — mirroring the reference feedback page's intent without inventing in-app ticket systems.
- Header nav mirrors the reference site's items: 文档 → `docs/`, 更新日志 → `changelog/`, 提交漏洞 → `security/`, 社区 → `community/`. Footer right link group mirrors the reference: 服务条款 → `terms/`, 隐私政策 → `privacy/`, 支持与反馈 → `support/`; GitHub stays on the left © row.
- Brand assets come from `packages/desktop/assets/` (Drora D-mark path, app icon) and `packages/desktop/assets/desktop-pet-catgirls/` (noir 夜墨 / snow 雪铃 / ginger 杏桃 idle atlases, copied verbatim into `website/assets/`). The website must not modify the source assets; copies are refreshed by re-copying.
- The hero app-window mock is rendered as real DOM + CSS (no screenshots), so it stays crisp on all DPIs. It is decorative content: it must not fetch anything, and any text inside it is presentational, not documentation.
- Pet sprites animate with CSS `steps()` frame walks over the 4x2 atlas grid (320x640 per frame, 8 frames, 5 fps idle loop matching the manifest). `prefers-reduced-motion` freezes the pets at frame 0 and disables all reveal animations.
- The site is bilingual (Chinese default, English toggle). All user-facing strings live in the i18n dictionary in `website/assets/js/main.js`, keyed by `data-i18n` attributes; the choice persists in `localStorage`. The hero mock's decorative chat lines are translated too.
- Download links point at the fork's GitHub Releases as fixed-tag snapshots (`https://github.com/CavinHuang/Drora/releases/download/v<X.Y.Z>/<artifact>`): release assets carry the version in their filename, so `releases/latest/download/` would break as soon as a newer release ships. The visible version literals across all pages form one snapshot that must be bumped together when a release ships. Links only use artifact names that actually exist in the target release (per README.md's download table): `Drora-<version>-win-{x64,arm64}.exe`, `Drora-<version>-mac-{arm64,x64}.dmg`, and the single-file CLI `drora-windows-x64.exe` / `drora-darwin-arm64` / `drora-linux-x64`. There are no Linux desktop installers; the site must not invent `.deb`/`.rpm`/`.AppImage` rows.
- The hero primary CTA detects the visitor platform (Windows/macOS/Linux) via user agent and relabels "适用于 <platform>"; detection failure falls back to Windows. No UA sniffing beyond this label.
- Deployment is the `Deploy website to GitHub Pages` workflow (`.github/workflows/deploy-website.yml`), a two-stage pipeline: a `check` job runs `scripts/check-website.mjs` (zero-dependency gate: every internal href/src/og:image/data-atlas resolves to a file, anchors exist on their target page, all internal links are relative per the subpath rule, `data-i18n` keys exist in the main.js dictionary and never wrap interactive children); the `deploy` job runs only on pushes to `main` (or manual dispatch) after `check` passes. Pull requests touching `website/**` get the check job but never deploy — the Pages environment is single and PR previews would overwrite production. The repo needs Pages source = "GitHub Actions" (one-time setting, already configured). The site must work from a subpath (`https://<owner>.github.io/Drora/`), so all asset URLs are relative, never root-absolute.
- The GitHub repository About panel (description, homepage, topics) points at the deployed site: homepage = the Pages URL, description = one-line positioning ("开源 AI 编程工作台 · 复刻自 ZCode" family), topics = short lowercase keywords. The About panel is repo metadata, not site content; it may only claim what the repository actually ships.

## Ownership and event order

```text
push to main (website/**) -> Pages workflow -> upload-pages-artifact(website/)
  -> deploy-pages -> https://<owner>.github.io/Drora/
```

The website owns nothing at runtime: no storage beyond the language preference key, no network calls, no analytics. It is presentation-only, mirroring the app's rule that marketing surfaces never own product state.

## Acceptance scenarios

- Desktop 1440px: all five home sections render in order; header stays fixed with blur; hero mock shows sidebar/chat/right panel like the reference site; the three pet sprites animate their idle loops.
- Mobile 390px: nav collapses behind a menu button; the hero mock hides the right panel and narrows the sidebar; cards stack single-column; download rows stay tappable.
- Changelog page: every listed version links to its real GitHub tag page; feature/fix bullets match the fork's merged history; the layout mirrors the reference release page at 1440px and collapses to a single column on mobile.
- Docs pages: the sidebar (shared `<docs-nav>`) highlights the current page and links to every sibling page; the right "本页目录" scrollspy highlights the section in view and hides itself on pages with fewer than two `h2` sections; both sidebars show at ≥1280px and collapse away below it (matching the reference site); every command/env key on the docs pages appears verbatim in README.md; ⌘K search navigates across doc pages.
- Language toggle switches every visible string without reload and persists across a reload — on every page.
- Header navigation highlights the current page (home/changelog/docs).
- `prefers-reduced-motion: reduce`: no scroll-reveal transitions, pets frozen.
- All download anchors resolve to `https://github.com/CavinHuang/Drora/releases/download/v<X.Y.Z>/...` URLs whose artifact names exist in that release.
- Offline/file:// open: every page renders fully (no CDN/font/network dependencies).
