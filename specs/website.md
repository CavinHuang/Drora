# Product website (GitHub Pages)

## Product rules

- The Drora product website is the `apps/website` workspace app: a Next.js (App Router, React 19) site statically exported for GitHub Pages (`output: "export"`, `basePath: "/Drora"`, `assetPrefix: "/Drora"`, `trailingSlash: true`). Deployment is the build artifact `apps/website/out`, produced by `pnpm --filter @drora/website build` and uploaded by the `Deploy website to GitHub Pages` workflow. Page inventory: `/` (home), `/docs/` (docs welcome) plus `/docs/[slug]/` for the docs IA, `/changelog/`, `/security/`, `/community/`, `/terms/`, `/privacy/`, `/support/`, and the App Router `not-found` (exported as `404.html`, which GitHub Pages serves automatically for the project site).
- Page bodies are **injected fragments**: the article content of each page lives in `apps/website/site-src/*.html` (`docs-<slug>.html`, `docs-index.html`, one file per secondary page, and the home page split `home-before.html` / `home-after.html` around the hero mock), mechanically migrated from the legacy vanilla site (`website/`, kept only as the migration source until the gates are green, then deleted wholesale). `page.tsx` renders its fragment via `dangerouslySetInnerHTML` inside a wrapper div; the home page composes `home-before` + a real-component hero mock + `home-after`. The transformation from the legacy pages is fixed: take the `<body>` children, drop the legacy page scripts (the root layout loads them globally), rewrite `data-base` to absolute form, and rewrite every internal href/src to a `/Drora/` absolute path. Fragment files and routes must stay 1:1 (enforced by `scripts/check-website.mjs`).
- The hero app-window mock is rendered from **real product components**: `apps/website/src/components/mock/` (WebsiteMock / HeroSidebar / RightPanelCards + `mock-data.mock.ts`) renders actual `packages/ui` components — imported through the controlled export `@drora/ui/website-hero` (`packages/ui/src/websiteHeroMock.ts`) — with committed mock data mirroring the reference site verbatim (Ryan Bot / zcode-\* groups / gomoku chat), the sole divergence being the user avatar (Drora D-mark). The mock is baked into the static HTML at **build time by a dedicated generator, not by Next**: `apps/website/scripts/generate-hero-mock.mjs` esbuild-bundles the mock subtree (tsconfig paths resolve the ui sources' `@/*.js` imports; asset imports stubbed empty) and renders it with `react-dom/server` `renderToStaticMarkup`, writing the committed fragment `src/components/mock/hero-mock.generated.html`, which `src/app/page.tsx` concatenates between the home fragments. Two hard constraints force this shape: the ui component chain uses React hooks, which Next 15's RSC compiler rejects inside the server module graph, and the mock must not hydrate — its `Date.now()` relative times are baked at build and a client re-render would mismatch (mock-recipe §5), so a `"use client"` boundary is off the table. Consequences: the mock ships zero JS, renders identically without JS, and is refreshed via `pnpm --filter @drora/website generate:hero-mock` (the package build script runs it automatically before `next build`; the baked relative times are build-moment snapshots by design). Known deliberate deviations: the active task highlight goes through `TaskList`'s public `activeTaskId` prop (zustand initial state is empty under SSR), and the mock's site chrome reuses the legacy site classes (`.mock-wrap`, `.window`, `.win-traffic`) under a `.dark` scope. `@drora/ui` source-internal `@/` imports are resolved by the generator's esbuild tsconfig-paths handling (the `@` webpack alias kept in `next.config.ts` is a harmless default, mirroring `packages/web/vite.config.ts`, for any future in-graph ui use); `apps/website` code itself never uses `@/`.
- Legacy site runtime assets live in `apps/website/public/assets/` (css/pets/docs images and the script trio, initially a verbatim copy of the legacy `website/assets/`): `style.css`, the custom elements in `components.js` (`<site-header>`, `<site-footer>`, `<docs-nav>`, `<drora-pet>`, `<release-block>`; light DOM, anatomy replicating the reference site), the i18n dictionary `i18n.js`, and the interactions in `main.js`. With the Next.js migration the **`public/` copy is the authoritative one**: `components.js` (docs-nav directory-form links) and `main.js` (search link form, title guard) already diverge from the frozen `website/` sources, which are kept only until the migration completes and are then deleted wholesale. The root layout loads all three scripts `afterInteractive`, after the injected DOM, so boot finds every `data-i18n` node. Since the hero-mock generator took over the ui render, the Next module graph itself imports no workspace packages (the `@drora/ui`/`@drora/shared` consumers are the generator-side mock sources); `transpilePackages` and the `@` webpack alias stay as harmless defaults for any future in-graph ui use. The shipped runtime is static HTML + these zero-dependency vanilla scripts — no client React hydration for page chrome. The site stays isolated from restored upstream code.
- All internal links and resource references — in fragments, in custom-element output, and in script-generated UI — are `/Drora/`-prefixed absolute paths ending in a trailing slash (`/Drora/docs/install/`); the docs welcome link is the docs base itself (`/Drora/docs/`). Directory-form links are mandatory (Next static export emits `<slug>/index.html` under `trailingSlash: true`; `.html` links would 404). `data-base` carries the prefix into the components: `site-header`/`site-footer` use `data-base="/Drora/"`, `docs-nav` uses `data-base="/Drora/docs/"`; `docs-nav` builds links as `data-base + slug + "/"` (welcome = `data-base` itself), and the ⌘K search overlay takes the same base from the sidebar's `docs-nav` (single source, cannot drift).
- **Host boundary in `src/app/globals.css`**: the import order is `@drora/ui/styles.css` (design tokens + the Tailwind engine the mock subtree needs) → legacy `style.css` → a **host-restore layer**. The ui stylesheet carries Electron-host globals by design — `html,body,#root{background:transparent !important}` for vibrancy, `body{overflow:hidden}`, and a `*:focus{outline:none !important}` clear (packages/ui/src/styles.css:48-66,122-133) — which on a plain web host produce a white-on-white site, locked scrolling semantics and invisible keyboard focus. The restore layer (kept strictly after the imports: same specificity, same `!important`, later rule wins) re-asserts `html,body{background:var(--bg) !important}` (single source: legacy `:root --bg`), restores legacy body geometry and `overflow-x:hidden`/vertical document scrolling, and restores a `:focus-visible` outline. Cascade layers are deliberately NOT used for this: under `@import ... layer(...)`, the ui `!important` declarations would _win_ the inverted important-layer race against unlayered restorations, and layering legacy style.css would let Tailwind's preflight override its element rules. The layer only touches element-level html/body rules and the focus ring; token/Tailwind utilities of the mock subtree are unaffected.
- The visual design intentionally follows the official ZCode marketing site (https://zcode.z.ai/): dark theme (`#161616` background, `rgba(255,255,255,0.1)` borders), Geist-style system font stack, and a five-section home layout — fixed header, hero with a live app-window mock, three-edition cards (mirroring the pricing card anatomy), three capability cards, download section, footer. Copy and branding are Drora's own and must follow `specs/drora-rename.md`; the site must never claim to be the official ZCode product.
- **Style parity pass (2026-10-10)** tuned chrome/typography to the reference site's measured values: header transparent with no blur (home/marketing `h=61`, docs pages solid `#161616` with a visible white/10 bottom border at `h=48`, scoped by `site-header[data-page="docs"]` — superseding the earlier "fixed header with blur" chrome), `--header-h: 48px` (docs sidebar/TOC sticky baseline), accent token `--blue: oklch(0.685 0.169 237.323)` (sidebar/TOC active color + border-left), body font stack led by the self-hosted `GeistSans` `@font-face`, docs layout = sidebar 280px with right border / article ≤776px / TOC 280px inside a `max-width:1152px` main shown only at `min-width:1280px` (`hidden xl:flex` semantics — min-width queries include the scrollbar, max-width ones do not), docs typography (h1 36/500, h2 30/500 with explicit `<hr>` separators instead of h2 border-tops, body 16/26 muted, lists with `disc` restored because the ui stylesheet's preflight strips `list-style`), marketing/legal heads (48px h1, legal override 48px line-height + white-88% body via `.page-narrow`), and changelog entry styling (pure-white version pill, 20px/500 section h2). Recorded intentional divergences from the reference: home capability cards keep their mini demo panels (pets/phone/goal float — real repo capabilities) atop reference card metrics; the configuration page's plan cards stay unported (free-open-source positioning); home hero/edition/download copy and ¥0 pricing are Drora positioning; the goal page keeps its merged「任务与目标模式」title pending product confirmation; the welcome page omits the reference's「本次版本亮点」section (needs copy sign-off); the mono stack has no self-hosted GeistMono asset yet (release pill falls back to `ui-monospace`); legal pages stay centered under the marketing hero rather than left-aligned on a 768px column.
- Because chrome components need JS to render, every fragment keeps a `<noscript>` fallback nav block with the same `/Drora/` absolute links. Without JS all article content (and the hero mock) still renders fully; navigation degrades to the noscript links.
- The docs section replicates the reference site's multi-page docs structure: one route per sidebar item, backstopped by one fragment per page under `apps/website/site-src/` (`docs-index.html` = welcome, `docs-install.html`, `docs-configuration.html` (连接模型), `docs-goal.html`, `docs-history.html`, `docs-remote-control.html`, `docs-remote-dev.html`, `docs-pets.html`, `docs-skin.html`, `docs-usage-stats.html`, `docs-skills.html`, `docs-subagents.html`, `docs-mcp.html`, `docs-hooks.html`, `docs-automation.html`, `docs-safety-confirm.html`, `docs-ADE-tools.html`, `docs-agents.html`, `docs-task-management.html`, `docs-memory.html`, `docs-cli.html`, `docs-build.html`, `docs-faq.html`, `docs-keyboard-shortcuts.html`). The route manifest is the `DOCS_SLUGS` const in `src/app/docs/[slug]/page.tsx` (`generateStaticParams`; `dynamicParams = false` — a slug outside the manifest 404s, no fallback branch). Every docs page renders the shared sidebar via `<docs-nav data-current="<slug>" data-base="/Drora/docs/">` (single source of the docs IA — `DOCS_IA` in `components.js`; current page highlighted), a breadcrumb row with its group label + 「复制全文」, the page h1, its own content, and a right "On this page" TOC auto-generated from the page's `h2[id]` elements (hidden below two). The sidebar taxonomy mirrors the reference docs groups (开始使用 / 核心功能 / 深度集成 / 更多 / 帮助), but items only cover capabilities this repository actually ships; z.ai-only features must not appear, and commands/env keys must be copied from README.md, not paraphrased.
- Docs search indexes the docs IA itself (the same data the sidebar renders, exposed by `docs-nav`): the ⌘K overlay lists matching doc pages and navigates to them in directory-link form. The index, the sidebar and the search share one source, so they cannot drift. Search and 复制全文 are progressive enhancements: without JS they simply don't render.
- Known transitional limitation (injected-body architecture): legacy `data-page`/`data-doc` body attributes are not preserved by fragment injection, so `main.js` per-page/per-doc titles are dormant; each route carries its own static `<title>`/metadata (root layout for now), and the language toggle only replaces `document.title` when the page actually declares `body[data-page]` — it never overwrites the static title with the home title. Revisit (body attributes or metadata per doc slug) when the injection phase is retired.
- The changelog page replicates the reference release-block anatomy: `border-b`-separated blocks, a meta row (white-bordered version pill, date, download dropdown for the latest release only), then the release title and feature/fix groups whose headings are `h2` elements. Secondary pages (`security/` 提交漏洞, `community/` 社区, `terms/` 使用条款, `privacy/` 隐私说明, `support/` 支持与反馈) mirror the reference site's navigation and footer targets, but their content stays faithful to what this community repository actually offers — explicitly community-run, no bounty program, no subscriptions/quotas/team plans, no in-app ticket systems. Header nav mirrors the reference items (文档 → `/Drora/docs/`, 更新日志 → `/Drora/changelog/`, 提交漏洞 → `/Drora/security/`, 社区 dropdown → `/Drora/community/` + 飞书/Discord/Discussions); the footer link group mirrors 服务条款/隐私政策/支持与反馈, GitHub stays on the left © row.
- Brand assets come from `packages/desktop/assets/` (Drora D-mark path, app icon) and `packages/desktop/assets/desktop-pet-catgirls/` (noir 夜墨 / snow 雪铃 / ginger 杏桃 idle atlases, copied verbatim into `public/assets/`). The website must not modify the source assets; copies are refreshed by re-copying. Pet sprites animate with CSS `steps()` frame walks over the 4x2 atlas grid (5 fps idle loop matching the manifest); `prefers-reduced-motion` freezes the pets at frame 0 and disables all reveal animations.
- The site is bilingual (Chinese default, English toggle). All user-facing strings live in the i18n dictionary in `public/assets/js/i18n.js`, keyed by `data-i18n` attributes; the choice persists in `localStorage`. Decorative mock text is zh-baked (aria-hidden) and not translated.
- Download links point at the fork's GitHub Releases as fixed-tag snapshots (`https://github.com/CavinHuang/Drora/releases/download/v<X.Y.Z>/<artifact>`): release assets carry the version in their filename, so `releases/latest/download/` would break as soon as a newer release ships. The visible version literals across all pages form one snapshot that must be bumped together when a release ships. Links only use artifact names that actually exist in the target release (per README.md's download table): `Drora-<version>-win-{x64,arm64}.exe`, `Drora-<version>-mac-{arm64,x64}.dmg`, and the single-file CLI `drora-windows-x64.exe` / `drora-darwin-arm64` / `drora-linux-x64`. There are no Linux desktop installers; the site must not invent `.deb`/`.rpm`/`.AppImage` rows. The hero primary CTA detects the visitor platform (Windows/macOS/Linux) via user agent and relabels "适用于 <platform>"; detection failure falls back to Windows. No UA sniffing beyond this label.
- Deployment is the `Deploy website to GitHub Pages` workflow (`.github/workflows/deploy-website.yml`), a two-stage pipeline: a `check` job runs `scripts/check-website.mjs` (zero-dependency gate over the fragments, the static equivalent of a build+out probe: every internal href/src/atlas is a `/Drora/` absolute link resolving to a fragment, route, or `public/assets/` file; cross-fragment anchors resolve — the home pair shares one id space; fragment↔route pairing and `DOCS_SLUGS`↔`docs-*.html` consistency; `data-i18n` keys exist in the i18n.js dictionary and never wrap interactive children; `data-base` contract per element); the `deploy` job runs only on pushes to `main` (or manual dispatch) after `check` passes, then `pnpm --filter @drora/website build` must succeed (second gate: the package build script bakes the hero mock first, and type errors plus prerender failures block deployment), its output must pass the out probe (`node scripts/check-website.mjs --out`: every expected route emitted, legacy assets copied, home carries the baked mock with `/Drora/`-absolute references and no `.html` links, docs pages carry the docs-nav skeleton), and only then is `apps/website/out` uploaded. Triggers cover `apps/website/**`, `packages/ui/**` and `packages/shared/**` (the home mock reuses ui components at build time), the check script, and the workflow file. Pull requests get the check job but never deploy — the Pages environment is single and PR previews would overwrite production. The repo needs Pages source = "GitHub Actions" (one-time setting, already configured). The site must work from the subpath `https://<owner>.github.io/Drora/` — hence the absolute `/Drora/` prefix rule above.
- **file:// offline behavior is a recorded, accepted degradation**: the legacy vanilla site could be opened straight from disk (relative links, no build); the Next.js export cannot — absolute `/Drora/` links, script loading and prerendered chunk URLs all assume an http(s) origin at (or below) the deployment path. Offline/local review means serving the artifact over a local static server (e.g. `npx serve apps/website/out`). The noscript fallback remains for JS-less browsers, not for file://.
- The GitHub repository About panel (description, homepage, topics) points at the deployed site: homepage = the Pages URL, description = one-line positioning ("开源 AI 编程工作台 · 复刻自 ZCode" family), topics = short lowercase keywords. The About panel is repo metadata, not site content; it may only claim what the repository actually ships.

## Ownership and event order

```text
push to main (apps/website|packages/ui|packages/shared …)
  -> check job: node scripts/check-website.mjs        (fragments / routes / i18n)
  -> deploy job: pnpm install --frozen-lockfile
     -> pnpm --filter @drora/website build             (type + prerender gate)
     -> upload-pages-artifact(apps/website/out)
     -> deploy-pages -> https://<owner>.github.io/Drora/
```

The website owns nothing at runtime: no storage beyond the language preference key, no network calls, no analytics. It is presentation-only, mirroring the app's rule that marketing surfaces never own product state. Build-time state (mock data, DOCS_IA, route manifest) is committed and single-sourced as described above.

## Acceptance scenarios

- GitHub Pages subpath: every page loads and navigates correctly under `https://<owner>.github.io/Drora/` — all internal links/assets are `/Drora/`-absolute with trailing-slash routes, prerendered chunks resolve under the base path, and the exported `404.html` covers unknown URLs (including out-of-manifest `/Drora/docs/<slug>/`).
- Dark theme holds at the document level: `getComputedStyle(document.body).backgroundColor` (and the html element's) resolves to `rgb(22, 22, 22)` on every route — the ui vibrancy layer must never win (host-restore layer above); hero/docs/changelog headlines are visible on the dark background, body scrolls vertically with horizontal clipping, and keyboard focus shows a visible ring.
- Desktop 1440px: all five home sections render in order; header stays sticky and transparent (no blur, reference-site chrome); the hero mock shows the sidebar/chat/right panel rendered from real `packages/ui` components (identical markup with and without JS); the three pet sprites animate their idle loops.
- Mobile 390px: nav collapses behind a menu button; the hero mock hides the right panel and narrows the sidebar; cards stack single-column; download rows stay tappable.
- Changelog page: every listed version links to its real GitHub tag page; feature/fix bullets match the fork's merged history; the layout mirrors the reference release page at 1440px and collapses to a single column on mobile.
- Docs pages: the sidebar (shared `<docs-nav>`) highlights the current page and links to every sibling page in directory form; the right "On this page" scrollspy highlights the section in view and hides itself on pages with fewer than two `h2` sections; both sidebars show at ≥1280px and collapse away below it; every command/env key on the docs pages appears verbatim in README.md; ⌘K search navigates across doc pages (same directory-form links).
- Language toggle switches every visible string without reload and persists across a reload — on every page; the static per-route `<title>` is never replaced by the home title.
- Header navigation highlights the current page (home/changelog/docs); `data-page` on the injected fragments drives it via `components.js`.
- `prefers-reduced-motion: reduce`: no scroll-reveal transitions, pets frozen.
- All download anchors resolve to `https://github.com/CavinHuang/Drora/releases/download/v<X.Y.Z>/...` URLs whose artifact names exist in that release.
- `node scripts/check-website.mjs` passes (fragments ↔ routes ↔ docs IA consistent, links/anchors/i18n/data-base clean), and `pnpm --filter @drora/website build` succeeds (hero mock baked, then Next static export) producing `apps/website/out` — route artifacts are `<route>/index.html` under `trailingSlash: true` (e.g. `out/docs/install/index.html`), with `out/index.html` and `out/404.html` at the root.
- Offline review: `npx serve apps/website/out` (or any static server) renders the whole site; direct `file://` open is out of scope (recorded degradation above).
