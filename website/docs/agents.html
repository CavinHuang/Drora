核心功能

Drora Agent

Drora Agent 是新建任务时最直接的提问入口。在同一个工作台里提出需求、补充上下文、引用文件、调用命令，并为当前任务选择模型与执行模式，让一次任务从需求理解一路推进到落地改动。

桌面应用以任务组织日常工作：每个任务有独立的会话、工具执行与 Git 上下文，输入框、文件引用与执行模式都围绕当前任务工作。对多步骤的复杂目标，可以配合目标模式承载长程计划。

工作台入口

在桌面端新建任务（ Ctrl/Command+N）即可开始与 Agent 对话。输入框提示： 向 Drora 提问，使用 @ 添加上下文，使用 / 选择命令或能力 ——先描述目标，再用触发符精准补充材料，通常能让 Agent 更快理解任务。

只是想问个问题、算点东西或起草一段文字，并不涉及某个代码仓库时，不必先选文件夹：在开始页选择「不在项目中工作」即可直接对话，这类对话同样收在侧栏任务列表里。注意对话结束不会撤销 Agent 已写入的文件，需要时请自行清理。

补充上下文

在输入框中键入触发符号，即可为当前任务快速补充上下文：

入口 触发符号 作用
添加附件 — 上传截图、文档、需求材料等文件，作为当前任务的上下文
引用上下文 @ 引用文件、文件夹、历史会话、白板或插件，让 Agent 精准定位相关材料
关联会话 # 关联已有任务，把历史对话的上下文带入当前任务
调用命令 / 调用已保存的命令，快速复用固定提示词或流程
调用技能 $ 唤起技能面板；部分输入法产生的全角 ¥ / ￥ 也会触发同一面板

项目指令文件

希望长期约束 Agent 的行为时，可以添加 AGENTS.md 指令文件：项目的技术栈与目录说明、代码风格与提交前要执行的验证命令、对高风险文件与生产配置的注意事项，以及团队协作约定，都适合写进去。Drora 启动任务时读取两个来源：

来源 路径 说明
用户全局指令 ~/.drora/AGENTS.md 跨项目通用的个人偏好与协作方式
工作区指令 <工作区>/AGENTS.md 当前项目专属的工程约定，视为任务的主要项目来源

两个来源都存在时，全局指令在前、工作区指令在后拼接注入；两者都不存在则不注入项目指令内容。

项目记忆

AGENTS.md 需要你亲自维护， Memory 记忆 则由 Agent 自动沉淀：把跨会话可复用的偏好、纠正与项目约束记下来，在后续会话中自动带上。独立 CLI 默认启用，桌面应用默认关闭，详见 Memory 记忆 。

执行模式

执行模式控制 Agent 修改文件、执行命令前的确认策略：是每步先确认、先出计划，还是尽量连续地完成任务。共享运行配置默认采用 build 权限模式；独立 CLI 通过 --prompt 执行非交互任务时，未指定 --mode 会采用 yolo。交互会话、桌面会话、恢复的任务及宿主可使用各自配置、保存或传入的模式。

执行模式 工作方式 适用场景
变更前确认 每次修改文件前先询问确认，也是默认档位 关键代码、生产配置等高风险改动
自动编辑 自动编辑文件 常规迭代开发，希望减少编辑确认
计划模式 编辑前先出计划，确认后再开始实施 需求复杂、步骤较多、希望先校准方案的任务
完全访问 减少确认次数，尽量连续执行 目标明确、上下文可信、希望快速推进的任务

聊天输入框聚焦时按 Ctrl+Shift+M 可在模式之间循环切换，也可以在输入框工具条的模式菜单里直接选择。权限确认的完整说明见 安全操作确认 。

推理强度

推理强度控制模型回答前的思考深度：通常越高越稳，但响应也会更慢一些。通过输入框工具条的推理强度菜单或 Ctrl+T 切换；可选档位随模型能力而定，从关闭到最高按需选择。默认档位适合大多数任务，追求更快响应时可降档。

辅助对话

主任务正在推进时想问一句「这个函数是干嘛的」，又不希望打断它的思路——辅助对话就是为这种情况准备的：它在右侧面板开一个独立对话，与主对话并行，互不干扰。

  • 在主对话输入框输入 /side 或 /btw，即可新建并打开一个辅助对话。
  • 选中主对话里的一段文字，从浮层选择「在辅助对话中提问」，选区会作为引用一并带过去。
  • 辅助对话继承主会话历史作为上下文，可以直接追问；它是功能完整的对话，能调用工具并走权限确认。
  • 主对话处于权限确认或提问等待状态时，划选入口不可用；草稿态与辅助对话自身也不能再开辅助对话。

辅助对话适合临时追问；需要长期保留的讨论，开一个正式任务更合适。

会话分叉

想在某一步换个方向试试，又不想弄丢现在的进度：把鼠标移到已完成的助手消息上，点操作行里的「分叉」，Drora 会以该消息的检查点为起点创建一个新任务，任务行带「从对话中派生」标记；原任务完整保留，继续按原样运行。

  • 任务结束后才可分叉，进行中或被中断的回复没有分叉入口。
  • 找不到分叉点检查点时无法分叉；分叉新建的是会话，不改变原任务。

使用建议

  1. 先描述目标：直接说明要实现、修复或分析的内容；多轮迭代的长任务用目标模式设定可校验的目标。
  2. 再补充上下文：用 @ 引用关键文件，或通过附件补充截图、文档和需求材料。
  3. 用命令和技能提效：固定流程用 / 调用命令，复用能力用 $ 调用技能。
  4. 按风险选执行模式：普通编辑用自动编辑；涉及关键文件或命令执行时，用计划模式先校准方案。
  5. 保持同一任务连续推进：持续追问、补充约束并查看改动，避免把上下文拆散。
