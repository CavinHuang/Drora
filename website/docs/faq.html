常见问题

在这里，我们汇总了关于 Drora 的产品定位、模型接入以及在使用过程中可能遇到的技术问题的解答。

1. Drora 的产品定位是什么？

Drora 是一个基于上游 ZCode 开源复刻的智能体开发环境（Agentic Development Environment，ADE）。与传统 IDE 不同，Drora 不以手动编写代码为核心，而是让 AI Agent 成为开发的主角——您只需用自然语言描述需求，Agent 即可驱动从编码、调试到预览的完整开发流程。

  • ADE 平台：围绕 Drora Agent 内置文件管理、终端、Git 提交及实时浏览器预览，通过自然语言指令驱动 Agent 完成全生命周期开发任务。
  • 全上下文感知：Agent 能够深入理解项目结构、文件内容以及 UI 视觉元素，无需记忆复杂的命令行参数。
  • 当前重点：围绕 Drora Agent 强化长任务执行和稳定性，把工作区、工具、模型、权限和 Review 串成连续的开发流程。

2. Drora 免费吗？

Drora 工具本身完全免费、开源。但作为开发者，您需要准备自己的 API Key 或模型服务套餐。目前支持以下接入方式：

  • 智谱系列：GLM Coding Plan 编程套餐、智谱开放平台模型资源包/充值余额、智谱 Z.ai。
  • 模型服务：Drora Agent 可使用已接入的模型服务和套餐。
  • 企业模型通道：团队统一维护、供 Drora Agent 稳定调用的模型通道。
  • 自托管服务：团队批准的私有化模型服务或专有网络模型资源。

3. 我的终端已配置好 GLM API，还需要在 Drora 重新配置吗？

需要。终端环境变量和 Drora 桌面端的模型配置是两套独立入口，配置不会自动同步。您可以选择以下任一方式：

  • 快速连接：在欢迎页面或个人头像处连接 BigModel/Z.ai 账号，若账户内有可用套餐将自动连接。
  • 手动管理：通过模型选择器底部的「管理模型」进入「模型设置」，手动添加 Base URL 和 API Key。

4. Connect 之后一直 Loading？

如果模型服务连接一直处于 Loading，请优先检查：

  1. 网络环境：确保当前网络可以访问对应模型服务。
  2. 账号权限：确保登录账号或 API Key 拥有可用额度和模型访问权限。

5. 怎么把整个文件夹作为上下文交给 Agent？

有两种方式，都可以。

用 @ 直接选：输入框中的 @ 选择器会同时列出文件和文件夹，也可以选择技能和智能体。输入 @ 后继续输入名称筛选，用方向键在候选项之间循环选择即可。

拖拽进输入框：

  • 从 Drora 左侧文件树中拖拽文件夹到输入框。
  • 从 Finder、资源管理器等系统文件管理器中拖拽文件夹到输入框。

无论哪种方式，Drora 都会把该文件夹作为上下文引用，Agent 可以围绕目录结构和其中的文件继续分析或执行任务。

6. GLM Coding Plan、Anthropic 端点、OpenAI 通用端点有什么区别？

BigModel（国内）与 Z.ai（海外）在供应商目录中提供「Coding Plan」与「标准 API」两类模板，对应不同的端点与计费来源（详见 连接模型 的端点说明）：

端点 典型地址（BigModel） 何时使用
Anthropic 接口（Coding Plan 模板） https://open.bigmodel.cn/api/anthropic 已开通 GLM Coding Plan，用「编程套餐」或 Coding Plan 模板接入 GLM-5.3 编程场景
OpenAI 通用 https://open.bigmodel.cn/api/paas/v4 开放平台模型资源包 / 充值余额，走 OpenAI 兼容协议

常见误区：

  • 只有资源包 / 余额，却选了 Coding Plan 模板 → Coding 端点仅限编程场景，不适用于通用 API。
  • 通过「编程套餐」账号授权（非 API Key）连接时，无需手动填端点，Drora 会自动路由。

海外 Z.ai 请将地址中的域名替换为 api.z.ai，路径规则相同。

7. 上下文容量显示得比模型实际窗口小？自定义模型的窗口怎么填？

每个模型条目都带一个「上下文窗口」值，Drora 按这个值计算容量，规则如下：

  • 新加的模型、或没带窗口信息的模型，默认按 20 万（200000）计算。这就是接入百万上下文模型后，容量仍显示 20 万的原因。
  • 模型 ID 以 [1m] 结尾会被识别为百万上下文，自动按 100 万处理，不需要手填。
  • 其他情况以你填写的数值为准——需要 1M 就填 1000000。

在「设置 → 模型供应商」里展开对应模型即可修改。注意：通过编程套餐（Plan）连接的内置 GLM 模型，窗口由产品统一固定、不可编辑；只有用 API Key 方式添加的模型才允许自己改。

会话显示的容量取自该会话「当前所选模型」的窗口，所以同一个项目里不同会话显示不同容量是正常的——旧会话沿用它当时用的模型。

8. 为什么远没用满就开始「自动压缩」？

自动压缩不是等窗口用满才触发，而是提前留出输出空间和安全缓冲：

触发点 = 上下文窗口 − 输出预留（至多 21000）− 约 13000 的安全缓冲
  • 输出预留取「最大输出 Token」与 21000 中的较小值，所以通常合计固定扣掉约 3.4 万 token。
  • 换算下来：128K 窗口约在 9.4 万 token 触发（约 73%），200K 约在 16.6 万，1M 约在 96.6 万。窗口越小，触发点占比越低，属正常现象。
  • 触发判定的计数包含本轮工具结果的实时估算，可能与界面显示的用量略有出入——所以有时看起来「没到线」就压缩了。

如果窗口本身还在按默认的 20 万计算（见上一条），提前压缩会更明显——先把窗口值填对，再看压缩时机。自动压缩目前没有可配置的开关或阈值。

9. 子智能体没有用我指定的模型？

分两种情况：

  • 内置的 general-purpose 和 Explore：可以在设置里分别为它们指定模型；不指定时继承父会话的主模型——这是设计行为。想让它们固定用某个模型，就在设置里配上持久覆盖，清空即恢复继承。
  • 自定义 / 工作区 / 插件子智能体：仍以各自 Markdown 文件里的 model 字段为准。

所以「派出去的子智能体跟着主会话的模型跑」在没有配置覆盖时是预期结果，不是故障。

10. 技能列表是空的，全局技能不显示？

先确认技能文件放对了位置：

  • 用户级（全局）： ~/.drora/skills/<技能名>/SKILL.md （也识别 ~/.agents/skills/ 下的同名结构）。
  • 工作区级： <工作区>/.drora/skills/<技能名>/SKILL.md （也识别 .agents/skills/）。

目录为空时，列表里自然不会有全局技能。确认目录里确实有技能后，再按这三步排查：

  1. 在「设置 → 技能」里按来源查看，确认没有被搜索框或来源筛选挡住。
  2. 新建或导入的技能需要点「刷新」才会出现。
  3. 检查每项右侧的启用开关是否处于开启状态。

完整的目录结构与导入方式见 技能与斜杠命令。

11. 换电脑，要复制哪些配置文件？

把这几处复制到新机器的相同位置，即可带走绝大部分配置：

路径 带走什么
~/.drora/cli/config.json MCP 服务器、权限默认值、插件与技能开关、Hooks 等 Agent 配置
~/.drora/v2/config.json 模型供应商配置（含 API Key、Base URL、模型列表）
~/.drora/AGENTS.md 全局规则
~/.drora/agents/ / ~/.drora/skills/ / ~/.drora/commands/ 自定义子智能体、技能、命令
<项目>/.drora/ 项目级配置，随仓库走，不用单独复制

不要复制这两个文件： ~/.drora/v2/credentials.json （登录凭据按设备加密，换机后无法解密，直接在新机器重新登录即可）和 ~/.drora/v2/telemetry-state.json （含设备标识，不应在两台机器间共用）。会话历史、日志等运行数据也不建议搬运。

12. ~/.drora/cli/exec 目录占了很多空间，能删吗？

能删。这个目录存放的是历史会话中终端命令的输出记录，目前不会自动清理，长期使用会越积越大。在 Drora 完全退出、且没有后台命令在跑的情况下，可以整个删除——Drora 会在需要时自动重建。删除的代价只是历史任务里的命令输出无法再回看，不影响任何配置和会话记录。

13. 在哪里查看 Drora 的版本号？

桌面端在标题栏菜单「帮助 → 关于 Drora」查看当前版本，「帮助 → 检查更新」的提示也会带版本号；CLI 在终端执行 drora --version。

14. 安装时提示「已损坏」或 SmartScreen 拦截？

社区构建未做签名：Windows 选择「更多信息 → 仍要运行」；macOS 在「系统设置 → 隐私与安全性」放行，或执行 sudo xattr -rd com.apple.quarantine /Applications/Drora.app。

15. 有 Linux 桌面版吗？

暂未提供 Linux 预编译安装包；Linux 用户可先使用 CLI 单文件（ drora-linux-x64 ），或从源码 pnpm bundle:desktop -- --os linux自行构建。

16. 如何更新？

桌面应用内置自动更新（latest 通道），也可以随时到 Releases 页下载新版本覆盖安装。

17. MCP 服务器连接失败怎么办？

在「设置 → MCP 服务器」查看该服务器的状态与失败原因：配置无效就检查字段填写；网络不可达就检查网络与代理；协议协商失败可在编辑服务器时把协议版本切换为「兼容旧版」；要求授权的服务重新「打开授权」。详见 MCP 与插件。

18. 指令发错了、文件被改坏了怎么办？

不用重开任务：悬停自己发送过的消息点「编辑」，改写后重发；需要回退文件时用「对话 + 文件重置」；每轮回复下方的文件变更摘要支持「撤销 / 重新应用」。详见 会话与编辑历史。

19. 遇到问题如何反馈？

欢迎到 GitHub Issues 提交问题，或加入 README 中的 社区渠道 交流。
