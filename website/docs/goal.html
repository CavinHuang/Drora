核心功能

任务与目标模式

面对要跑很久的复杂任务，可以用 /goal给当前会话设一个目标。设定之后，Agent 会围绕这个目标持续推进：每一轮结束都自动校验是否达成，没达成就自己接着下一轮，确认完成才收尾——把「盯着 Agent 一步步催」交给运行时。

  • 适合「一句话说得清、但要多轮才能做完」的任务：重构一个模块、清完一批类型错误、把某个指标调到目标值。
  • 摘要面板的目标卡片实时展示目标状态、token 与时间用量、迭代轮次。
  • 待办清单按迭代轮次分组，每一轮推进了什么一目了然。
目标写得越具体、越可校验，自动推进就越稳：把要改的文件、要通过的测试、要达到的指标写进目标描述里。

设定目标

在会话输入框输入 /goal加一句话即可设定目标。同一会话同时只有一个目标；不带参数的 /goal可随时查看当前目标：

/goal # 查看当前目标（描述、状态与用量） /goal <目标描述> # 设定目标并立即开始推进 /goal replace <目标描述> # 不经确认直接替换现有目标 /goal pause # 暂停自动推进 /goal resume # 恢复推进 /goal clear # 清空目标

目标最长 4000 字符；不带 replace设定时若已有目标，会先要求确认是否覆盖。headless 模式下也可以在单次运行中设定目标：

drora -p "继续修复剩余的类型错误" --target "类型检查全部通过" --target-replace

摘要面板中的目标卡片展示目标描述与状态（进行中 / 已暂停 / 预算受限 / 已完成），以及 token、时间用量和已进行的迭代次数；待办清单按「第 N 轮迭代」分组，清单项归属它首次出现的轮次。

每轮自动校验

每一轮结束后，运行时会发起一次独立的完成校验，对照目标逐项核对当前实际状态，产出通过与否、原因和下一步建议。校验未通过时，结果会注入下一轮继续推进；通过才把目标置为已完成并收尾总结。

校验看的是实据——改动的文件、命令输出、测试结果；待办没做完就不会被判成完成，完成与否由校验裁定，模型不能自行宣布完成。会话时间线中每次校验以分隔条呈现：

  • 目标校验中
  • 目标未完成，任务继续
  • 目标已完成，任务结束

中途介入

随时可以暂停、恢复或清空目标：暂停不丢失上下文，恢复后从当前状态继续推进。目标停止自动推进只有三种情况：

  • 完成校验通过，目标收尾；
  • 你主动暂停或清空；
  • 你中断了正在推进的一轮，校验随之中断，等待你的下一条指令。

什么情况下设不了目标

  • Plan 模式：计划模式与自动续跑冲突，目标只记录、不会自动继续——请切换到其他执行模式后再设。
  • 任务运行中：请等当前任务结束或先停止，再设定目标。

与执行模式搭配

目标和执行模式职责不同：目标管「何时算完」，执行模式（build / edit / plan / yolo）管「哪些操作需要确认」。跑长目标可以搭配自动化程度更高的模式，让推进不被确认打断；涉及重要改动的目标，用更严格的模式保留每一步确认。
