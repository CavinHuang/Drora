Hooks

Hook 用来在特定事件时机自动执行本地命令——在会话开始时注入团队约束、在工具调用前做安全检查、在主模型结束后追加校验。Hook 本质上是一个本地子进程协议：运行时把事件写成一行 JSON 传给它的 stdin，Hook 通过退出码和 stdout 返回结果。

执行顺序与事件

一次会话按「会话开始 → 用户提交输入 → 工具调用前 → 权限询问 → 工具调用后 → 工具失败后 → 主模型结束」的顺序触发事件；每个事件下可以挂多条 Hook，同一事件的多条 Hook 按声明顺序依次执行。共 7 个事件：

事件 matcher 匹配值 作用
SessionStart 会话来源：startup / resume / clear / compact 会话开始时补充上下文
UserPromptSubmit —（不适用） 补充上下文，或阻断本次模型请求
PreToolUse 工具名（如 Bash） 允许 / 询问 / 拒绝工具调用，或改写工具输入
PermissionRequest 工具名 自动允许或拒绝权限询问
PostToolUse 工具名 工具完成后补充上下文
PostToolUseFailure 工具名 工具失败后补充上下文
Stop —（不适用） 追加上下文，或让主模型再继续一轮

配置来源

来源 位置 信任
用户配置 ~/.drora/cli/config.json 的 hooks 段 你自己的配置，直接生效
项目配置 项目根 drora.json 或 .drora/config.json 按工作区审查信任，见下文安全边界
插件 插件目录内的 hooks/hooks.json 随插件一起安装与启用
Hooks 默认关闭：用户与项目配置都需要在 hooks 段写 enabled: true 才会启用。Hook 配置变更将在新会话中生效，不影响进行中的会话。

快速上手：第一条 Hook

在用户配置（~/.drora/cli/config.json）里加入如下 hooks 段：每次调用 Bash 工具前，先运行守卫脚本，由它决定放行、转人工确认还是拒绝：

{ "hooks": { "enabled": true, "events": { "PreToolUse": [ { "matcher": "Bash", "hooks": [ { "type": "command", "command": "node ${DRORA_PROJECT_DIR}/scripts/guard.js", "timeoutMs": 10000 } ] } ] } } }

守卫脚本从 stdin 读到事件 JSON，向 stdout 打印一行 JSON 即可参与决策——例如要求改动 dist 目录的命令先经人工确认：

{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"ask","permissionDecisionReason":"该命令会改动 dist 产物目录"}}

打开一个新会话，触发一次 Bash 调用即可验证：守卫脚本的判断会出现在工具调用前，拒绝与拦截原因会随会话记录留痕。

执行器、超时与 matcher

每条 Hook 二选一指定运行方式：

type 关键字段 说明
process command、args 以子进程直接运行，不经 shell 解析
command command、async、shell、timeout / timeoutMs 经 shell 执行；async 为 true 时后台运行
  • 超时：单条 Hook 默认 60 秒（hooks.timeoutMs可整体调整）；Hook 自带的 timeoutMs优先，command 型的 timeout按秒计。超时按失败处理。
  • 输出上限：maxOutputBytes默认 32 KiB，超限会被截断。
  • 后台运行：command 型设置 async: true后独立于当前回合执行，输出不会反向影响已经继续的动作。
  • matcher：省略或 * 匹配全部；a|b|c 形式按精确枚举；其余写法按正则表达式匹配。

stdin 输入契约

运行时向 Hook 的 stdin 写入一行 JSON。所有事件都携带会话公共字段；工具类事件追加工具字段，Stop 事件追加响应字段。常用字段：

字段 说明
session_id 会话 ID
hook_event_name 触发的事件名
permission_mode 当前权限模式（build / edit / plan / yolo）
cwd 会话工作目录
transcript_path 会话转写（JSONL）临时文件路径
tool_name / tool_input / tool_use_id 工具类事件提供：工具名、输入参数与调用 ID
prompt UserPromptSubmit 提供本次用户输入
tool_response / last_assistant_message / stop_hook_active PostToolUse 提供工具结果；Stop 提供最终回复与是否已由 Hook 续跑过

环境变量：Hook 进程会拿到 DRORA_SESSION_ID与 DRORA_PROJECT_DIR（插件 Hook 另有插件根目录与 ID 等变量）；command 与 args 里的 ${DRORA_PROJECT_DIR}等占位符会在运行前展开。

stdout、退出码与常用返回值

退出码 0 时，stdout 会按一行 JSON 解析；不需要决策的 Hook 直接正常退出即可，打印的非 JSON 文本只作为诊断信息。按事件常用的返回：

PreToolUse：拒绝或改写工具调用

permissionDecision 取 allow、ask 或 deny；updatedInput 可整体替换工具输入（替换后的输入会重新校验）：

{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"禁止对生产目录执行删除命令"}}

PermissionRequest：自动允许或拒绝权限询问

decision.behavior 取 allow 或 deny；allow 可附带 permissionUpdates 把规则加入权限配置：

{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"deny","message":"部署脚本需在人工监督下执行"}}}

UserPromptSubmit：补充上下文或阻断请求

additionalContext 会注入本次请求；continue 设为 false 则在模型调用前阻断本次输入：

{"continue":false,"stopReason":"仓库处于发布冻结期，本次提交被拦截"}

Stop：让主模型再继续一轮

decision 设为 block 并给出原因，主模型会带着原因继续一轮收尾工作；最多连续续跑 3 次，防止无限循环：

{"decision":"block","reason":"测试尚未全部通过，请继续修复"}

退出码

退出码 含义
0 成功：stdout 按一行 JSON 解析为返回值
2 阻断：stderr（缺省用 stdout）作为拦截原因，等价于拒绝
其他非零 Hook 自身失败（可恢复），不改变当前动作

安全边界与信任审查

Hook 是在沙盒外运行的任意本地命令，请只启用自己审查过的配置。项目级 Hook 按工作区身份与声明摘要（SHA-256）记录信任：首次发现需要你在审查中确认，声明一经改动就要重新审查。Hook 的运行明细（结果、耗时、拦截原因）随会话记录留存，可以在会话中查看是哪条 Hook 拦截了请求。

在设置页管理 Hook

桌面端「设置 → 钩子」里可以新建、编辑、启停和删除 Hook：选择事件、运行方式（进程或 Shell 命令）与匹配器，无需手写配置；同一页也会列出已安装插件的 Hook 和可导入的既有 Hook 配置。

工具生态的另一种接入方式见 MCP 与插件。
