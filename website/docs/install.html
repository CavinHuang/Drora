开始使用

安装

无需从源码构建，下载对应平台的产物即可使用。全程通常只需两分钟：下载安装包 → 完成安装 → 首次启动连接模型。

下载

无需从源码构建，直接在 Releases：

文件 说明
Drora-<版本>-win-x64.exe / win-arm64.exe Windows 桌面应用安装包（NSIS）
Drora-<版本>-mac-arm64.dmg / mac-x64.dmg（及 .zip） macOS 桌面应用
drora-windows-x64.exe / drora-darwin-arm64 / drora-linux-x64 Agent CLI 单文件，须在终端中运行（双击会闪退）

暂不提供 Linux 桌面安装包，Linux 用户可先使用 CLI 单文件，或从源码自行构建桌面应用。

安装步骤

macOS

打开下载的 DMG，把 Drora 拖入「应用程序」，然后从启动台或应用程序文件夹启动。

Windows

运行下载的 .exe 安装程序，按向导完成安装，然后从开始菜单或桌面快捷方式启动。

Agent CLI

单文件可执行，放到 PATH 目录或直接以路径运行；必须在终端中启动，双击会闪退。首次使用先执行 drora login完成浏览器授权，即可开始提问。

首次运行与签名提示

安装包未做签名：Windows 首次运行请在 SmartScreen 提示时选择「更多信息 → 仍要运行」；macOS 首次打开若被拦截，可在「系统设置 → 隐私与安全性」中放行，或执行 sudo xattr -rd com.apple.quarantine /Applications/Drora.app。

校验与更新

所有产物均由 GitHub Actions 从源码构建， SHA256SUMS.txt提供校验和。

桌面应用内置自动更新（latest 通道），也可以在「帮助 → 检查更新」手动检查；随时可到 Releases 页下载新版本覆盖安装。

CLI 单文件没有自更新：重新下载新版本的 drora-<os>-<arch>替换旧文件即可。

网络代理

走公司网络或代理上网时，在设置的「HTTP 代理」中填写代理地址（如 http://127.0.0.1:7890），模型、MCP、命令工具与应用渲染层的出口流量都会经过它。

留空不等于跟随系统：代理字段为空时出口流量直连，不会读取系统代理环境变量——「终端里能联网而应用不行」多半是这个原因。
设置项 用途
HTTP 代理 如 http://127.0.0.1:7890；留空时直连
不使用代理的地址 逗号分隔的主机列表，匹配的请求直连、不经过代理
自定义证书 PEM 根证书文件路径（企业 HTTPS 解密网关场景），会作为 NODE_EXTRA_CA_CERTS 注入模型、MCP 与命令工具

代理设置修改后需重启应用生效。CLI 侧可在用户配置文件 ~/.drora/cli/config.json 中设置 network.httpProxy、 network.noProxy、 network.caCertFile，语义相同。

Windows 专属设置

设置中可开启「关闭窗口时隐藏到托盘」：开启后点击关闭按钮只会隐藏窗口到系统托盘，托盘菜单中的退出才会完全退出应用。该设置仅 Windows 生效。

故障排查

macOS 提示「已损坏，无法打开」

这是未签名安装包被 Gatekeeper 隔离的正常表现，执行 sudo xattr -rd com.apple.quarantine /Applications/Drora.app 解除隔离后再打开。

Windows 安装或启动被拦截

在 SmartScreen 提示时选择「更多信息 → 仍要运行」。安装包未做代码签名，安全软件的拦截提示属于预期行为。

CLI 提示没有执行权限

macOS / Linux 下载的单文件需要执行权限： chmod +x drora-* 后再运行。
